# タスク（Tasks）ディレクトリ

タスク分割工程（Tasks）の成果物を格納するディレクトリです。
設計ドキュメント（`docs/design/`）を受け取り、実装可能な単位に分割します。

## ファイル構成

```
tasks/
├── task-list.md          # タスク一覧（スプリント/マイルストーンごと）
├── sprint-01/            # スプリントごとにフォルダ分けも可
│   └── task-list.md
└── archive/              # 完了したスプリントのアーカイブ
```

## タスク分割の基本ルール

### 粒度の基準：「80分以内」

> 1タスク = 1PR = レビュアーが80分以内でレビュー完了できる単位

- **大きすぎる場合**（8pt以上）: さらに分割する
- **小さすぎる場合**（0.5pt以下）: 関連タスクとまとめる
- **判断が難しい場合**: 実装者とレビュアーが相談する

### タスクと仕様書・Issueの紐付け

タスクは必ず仕様書の Spec ID または Issue に紐付ける。
紐付けられないタスクは、仕様化が不十分なサインである。

```
仕様書（SPEC-XXX）
  └── Issue #123（要件定義・合意形成）
        └── T-01: [実装タスク]（PR #456）
        └── T-02: [テストタスク]（PR #457）
```

### 依存関係の管理

タスク間に依存関係がある場合は明示する。
並行して進められるタスクは最大限並行させる。

```
T-01 → T-03（T-01完了後にT-03開始）
T-02 → T-03
T-01, T-02 が並行可能
```

## AIを活用したタスク分割

### プロンプト例（Cursor/Claude）

```
以下の仕様書と設計書をもとに、実装タスクを分割してください。

【仕様書】
（docs/spec/xxx.md の内容を貼り付ける）

【設計書】
（docs/design/architecture.md の内容を貼り付ける）

【条件】
- 1タスク = 1PRで完結する単位
- 各タスクにはSpec IDとIssue番号を紐付ける
- 見積もりポイント（1/2/3/5/8）を付与する
- 依存関係がある場合は明示する
- Markdown の表形式で出力する
```

### AI出力のレビューポイント

- [ ] タスクが仕様書の全要件をカバーしているか
- [ ] 1タスクが大きすぎないか（8pt以上は要分割）
- [ ] テスト・ドキュメント更新のタスクが含まれているか
- [ ] 依存関係が正しく定義されているか

## バーンダウンチャートの作成

バーンダウンデータ（`task-list.md` 末尾）をもとに、
以下のツールでチャートを作成できます：

- **GitHub Projects**: Issue をボードで管理
- **Mermaid**: `docs/design/diagrams/` に Mermaid チャートを追加
- **スプレッドシート**: Google Sheets / Excel で可視化
