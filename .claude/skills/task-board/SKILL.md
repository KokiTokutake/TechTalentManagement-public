# /task-board — タスクボード状態確認

**使う場面**: 工程4・5（タスク管理・実装中）。スプリントの進捗を把握したいとき。朝会・進捗確認で使う。

---

## 目的

`tasks/task-list.md` と GitHub の Issue 状態をもとにタスクボードを表示し、
スプリントの進捗・ブロッカー・バーンダウンを可視化する。

---

## 実行手順

### STEP 1: タスク情報の収集

`tasks/task-list.md` を読み込む。
可能な場合は `gh issue list` でGitHub の最新状態も参照する。

### STEP 2: タスクボードの表示

```markdown
## 📋 タスクボード（YYYY-MM-DD）

### スプリント進捗: X / Y SP 完了（X%）
[████████░░░░░░░░] 50%

### 🔴 未着手（X SP）
| TASK-ID | タスク名 | Spec | SP | 担当 | 備考 |
|---------|---------|------|----|----|------|
| TASK-003 | ログイン UI 実装 | SPEC-AUTH-001 | 2 | - | TASK-001 完了後に開始可 |

### 🟡 進行中（X SP）
| TASK-ID | タスク名 | Spec | SP | 担当 | ブランチ |
|---------|---------|------|----|----|---------|
| TASK-001 | ログイン API 実装 | SPEC-AUTH-001 | 3 | @dev | feat/42-login-api |

### 🔵 レビュー中（X SP）
| TASK-ID | タスク名 | PR | SP | 担当 |
|---------|---------|-----|----|----|
| TASK-005 | 設計書更新 | #38 | 1 | @tl |

### ✅ 完了（X SP）
| TASK-ID | タスク名 | PR | SP |
|---------|---------|-----|---|
| TASK-000 | Constitution.md 初版 | #35 | 1 |

### ⛔ ブロック中
| TASK-ID | 理由 | 対応者 |
|---------|------|--------|
| - | - | - |
```

### STEP 3: リスク・ブロッカーの確認

```
❓ 確認事項:
- ブロックされているタスクはありますか？
- 期限に間に合わないリスクがありますか？
```

ユーザーが「ブロックあり」と答えた場合:
- ブロック内容を task-list.md に記録する
- 「誰に確認・エスカレーションが必要ですか？」と確認する

### STEP 4: バーンダウン確認

スプリント残日数とSP残量からバーンダウンを計算して表示する:

```
📉 バーンダウン
スプリント残: X 日
残 SP: X / Y
1日あたりのペース: X SP/日（目標: Y SP/日）

⚠️ このペースでは完了しない可能性があります → スコープ調整を検討してください
```

### STEP 5: 次のアクション提案

状況に応じてアクションを提案する:

- 未着手タスクがある場合: `/task-start TASK-XXX → 次のタスクを開始できます`
- レビュー中が詰まっている場合: `PR レビューが溜まっています。レビューを優先してください`
- ブロックがある場合: `ブロックを解消するために @xxx に確認が必要です`
- 完了 SP が多い場合: `進捗良好です！/spec-list approved で次のタスクを計画できます`
