# /sdd-skills — スキル一覧表示

**使う場面**: いつでも。使えるスキルを確認したいとき、次に何をすべきか迷ったとき。

---

## 目的

SDD ハーネスで使えるスキルを工程別に一覧表示し、現在の状況に応じた次のアクションを提案する。

---

## 実行手順

### STEP 1: 現在の状況の把握（任意）

「現在どの工程にいますか？」と確認する。
「わからない」または「確認したい」の場合は `/sdd-health` を実行するよう案内する。

### STEP 2: スキル一覧の表示

```markdown
## 🛠️ SDD スキル一覧

### 🚀 導入・セットアップ
| スキル | 使う場面 |
|--------|---------|
| `/sdd-start` | 新プロジェクトへのSDD導入ウィザード（最初の一回） |
| `/sdd-health` | SDD遵守状況の健全性チェック（定期実行推奨） |
| `/sdd-skills` | このスキル一覧を表示 |

### 工程1: 原則決定（Constitution）
| スキル | 使う場面 |
|--------|---------|
| `/charter-create` | Constitution.md を対話型で作成する |
| `/charter-review` | Constitution.md を5観点でレビューする |

### 工程2: 企画・要件定義（Specify）
| スキル | 使う場面 |
|--------|---------|
| `/spec-write` | 仕様書を対話型で作成する（コーディング前に必ず） |
| `/spec-review` | 仕様書を5軸レビューする（approved にする前に） |
| `/spec-list` | 仕様書の一覧とステータスを確認する |
| `/spec-change` | 実装中に仕様変更が必要になったとき |

### 工程3: 設計計画（Plan）
| スキル | 使う場面 |
|--------|---------|
| `/design-create` | アーキテクチャ・コンポーネント設計書を作成する |
| `/design-review` | 設計書と仕様書の整合性を確認する |

### 工程4: タスク分割（Tasks）
| スキル | 使う場面 |
|--------|---------|
| `/tasks-plan` | 承認済み仕様書からスプリントタスクを分割する |
| `/task-board` | タスクの進捗状況を確認する（朝会・進捗確認） |

### 工程5: 実装（Implement）
| スキル | 使う場面 |
|--------|---------|
| `/task-start` | タスクを選んで実装を開始する（ブランチ作成） |
| `/impl-guide` | 実装ガイダンスを取得する（仕様書・設計書の読み込み） |
| `/impl-check` | 実装が受入基準を満たしているか確認する（PR前） |
| `/task-done` | タスク完了・PR作成・レビュー依頼 |

### 工程5→6: テスト自動化（Test）
| スキル | 使う場面 |
|--------|---------|
| `/test-write` | 仕様書の受入基準から Playwright テストを自動生成 |
| `/test-run` | Playwright テストを実行して結果を確認 |
| `/test-report` | テスト結果レポートを生成・仕様書へ反映 |

### 工程6: 検証・受入（Verify）
| スキル | 使う場面 |
|--------|---------|
| `/accept-run` | 受入テストを実施してPOサインオフを取得する |
| `/spec-trace` | 仕様書と実装コードの対応関係を確認する |

### 工程7: 移行・運用（Operation）
| スキル | 使う場面 |
|--------|---------|
| `/release-prep` | リリース準備（リリースノート・デプロイチェックリスト） |
| `/incident-handle` | インシデント対応ガイド（本番問題発生時） |
| `/retro-run` | レトロスペクティブの実施（スプリント終了後） |

### 🧠 継続学習（Learning）
| スキル | 使う場面 |
|--------|---------|
| `/review-learn` | マージ済みPRのレビュー指摘を自動抽出してパターンDBに蓄積 |
| `/review-patterns` | 蓄積パターンの閲覧・検索（仕様書・設計書作成前に参照） |

### 🖥️ PM ツール（Web プロジェクト管理）
| スキル | 使う場面 |
|--------|---------|
| `/pm-setup` | SDD PM ツールの初期設定（プロジェクト開始時） |
| `/sprint-start` | 新スプリントの開始（ゴール・タスク設定） |
| `/sprint-end` | スプリント完了・ふりかえりへの引継ぎ |
| `/pm-sync` | PM ツール ↔ プロジェクトファイル双方向同期 |

---

合計: 31スキル
```

### STEP 3: 現在の工程に応じたオススメを表示

ユーザーが工程を答えた場合、その工程のスキルを強調表示して次のアクションを提案する:

```
現在: 工程2（要件定義）

📌 今すぐ使えるスキル:
  /spec-write   → 仕様書を作成する
  /spec-review  → 作成済み仕様書をレビューする
  /spec-list    → 仕様書の状態を確認する

✅ 工程2が完了したら:
  /design-create → 工程3（設計）へ進む
  /tasks-plan    → 設計をスキップして工程4（タスク分割）へ進む
```

## クイックリファレンス

```
最初の一回:           /sdd-start
仕様書を書く:         /spec-write → /spec-review
タスクを管理する:     /tasks-plan → /task-start → /task-done
実装を進める:         /impl-guide → /impl-check
テスト自動化:         /test-write → /test-run → /test-report
リリース準備:         /accept-run → /spec-trace → /release-prep
振り返り:             /retro-run
継続学習:             /review-learn → /review-patterns
困ったとき:           /sdd-health

PM ツール:            /pm-setup → /sprint-start → /sprint-end → /retro-run
```
