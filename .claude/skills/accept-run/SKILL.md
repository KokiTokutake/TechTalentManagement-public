# /accept-run — 受入テストの実施・PO サインオフ

**使う場面**: 工程6（検証・受入）。スプリント完了後にプロダクトオーナーの受入確認を実施するとき。

---

## 目的

仕様書の受入基準に基づいた受入テストを実施し、`docs/guides/acceptance-checklist.md` に結果を記録して
プロダクトオーナーのサインオフを取得する。

---

## 実行手順

### STEP 1: 対象仕様書の確認

「今回の受入確認の対象は何ですか？」と確認する。
- スプリント全体 → 全 approved 仕様書を対象にする
- 特定機能 → Spec ID を指定する

### STEP 2: 受入チェックリストの生成

対象仕様書の受入基準を `docs/guides/acceptance-checklist.md` テンプレートに転記して生成する:

```markdown
## 受入確認チェックリスト: [スプリント名/機能名]

実施日: YYYY-MM-DD
実施者: @handle
確認環境: staging / production

### SPEC-AUTH-001: ログイン機能

| # | 受入基準 | 結果 | 備考 |
|---|---------|------|------|
| 1 | 正しい認証情報でログインできる | ✅/❌/⚠️ | |
| 2 | 誤ったパスワードで "認証に失敗しました" と表示される | ✅/❌/⚠️ | |
| 3 | 5回連続失敗でアカウントがロックされる | ✅/❌/⚠️ | |
```

### STEP 3: テスト実施の案内

各受入基準について、テスト手順を案内する:

```
📋 受入基準 1 のテスト手順:
1. ステージング環境（https://staging.[domain]）にアクセスする
2. テストアカウント（test@example.com / Test1234!）でログインする
3. ログイン後にダッシュボードが表示されることを確認する
4. ブラウザの Network タブで JWT トークンが返ってくることを確認する

結果は？: ✅ 合格 / ❌ 不合格 / ⚠️ 部分的
```

ユーザーが回答するたびに次の基準に進む（対話型で一つずつ進める）。

### STEP 4: 問題発見時の対応

❌ または ⚠️ の項目があった場合:

```
❌ 受入基準2が失敗しています

詳細を教えてください:
- 実際にどういう動作をしましたか？
- エラーメッセージはありましたか？
- 再現手順を教えてください

→ `/bug-triage` を実行してバグの分類・修正パスを決定してください。
```

### STEP 5: チェックリストの保存

全項目が確認できたらチェックリストを `docs/guides/acceptance-checklist.md` に保存する。

### STEP 6: PO サインオフの確認

```
📝 プロダクトオーナーのサインオフ

全受入基準の確認結果:
  合格: X 件 / 不合格: X 件 / 部分的: X 件

この機能/スプリントのリリースを承認しますか？
  [承認する] → リリース準備を開始 (/release-prep)
  [承認しない] → バグ修正後に再確認
```

---

## 出力ファイル

- `docs/guides/acceptance-checklist.md`（更新）

---

## 次のステップ

```
全件承認の場合:  /release-prep → リリース準備を開始
不合格ありの場合: /task-start [bug修正タスク] → バグ修正を開始
```
