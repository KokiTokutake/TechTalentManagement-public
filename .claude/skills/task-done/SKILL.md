# /task-done — タスク完了・PR 作成

**使う場面**: 工程5（実装）。実装が完了し、PR を作成してレビューに出すとき。

---

## 目的

受入基準の達成確認・PR の作成・タスクステータス更新を漏れなく実施し、
仕様書との整合性が担保された状態でレビューに出す。

---

## 実行手順

### STEP 1: 現在のブランチ・タスクの確認

現在のブランチ名からタスク ID を特定し、対応するタスク情報を表示する。

```
現在のブランチ: feat/42-login-api-endpoint
対応タスク: TASK-001（ログイン API エンドポイント実装）
対応仕様書: SPEC-AUTH-001
```

### STEP 2: 受入基準のセルフチェック

仕様書の受入基準を一覧表示し、各項目を確認する:

```
📋 受入基準チェック（SPEC-AUTH-001）

以下を一つずつ確認してください:
[ ] Given: 正しい認証情報 / When: POST /login / Then: 200 + JWT 返却
[ ] Given: 誤ったパスワード / When: POST /login / Then: 401 返却
[ ] Given: 5回連続失敗 / When: POST /login / Then: アカウントロック

全て ✅ になりましたか？
```

未確認の項目がある場合は「まだ実装されていない受入基準があります。続けますか？」と確認する。

### STEP 3: テストの確認

```
確認:
- 受入基準に対応するテストコードは書きましたか？
- ローカルでテストが全て通過しましたか？（通過を確認したら続けます）
```

### STEP 4: コードの最終確認

```bash
# 変更ファイルの確認
git diff --stat main

# 未コミットファイルの確認
git status
```

コミット漏れがある場合は警告する。

### STEP 5: PR の作成

```bash
gh pr create \
  --title "feat: SPEC-AUTH-001 ログイン API エンドポイント実装 (#42)" \
  --body "..." \
  --label "enhancement"
```

PR の本文は `.github/pull_request_template.md` をベースに以下を自動入力する:
- 対応 Spec ID とリンク
- 受入基準の転記（チェックリスト形式）
- 変更ファイルのサマリー
- テスト実施の記録

ユーザーに確認してから実行する。

### STEP 6: レビュアーの設定

CODEOWNERS の設定に基づいてレビュアーを自動で設定する。
「レビュアーを追加しますか？」と確認する:

```bash
gh pr edit [PR番号] --add-reviewer @tech-lead-handle
```

### STEP 7: タスクステータスの更新

```
tasks/task-list.md の TASK-001 を「進行中」→「レビュー中」に更新しますか？
```

### STEP 8: 完了報告

```
✅ PR 作成完了

PR: https://github.com/[org]/[repo]/pull/42
ブランチ: feat/42-login-api-endpoint → main
レビュアー: @tech-lead-handle

次のアクション:
  レビュー承認後に CI が通過したらマージできます
  /task-board でタスクの進捗を確認できます
```

---

## 注意事項

- テストが通過していない状態でPRを出さない
- 受入基準を全て確認してからPRを出す
- 仕様書に書いていない機能を追加していないか確認する
