# /task-done — タスク完了・PR 作成

**使う場面**: 工程5（実装）。実装が完了し、PR を作成してレビューに出すとき。

---

## 目的

受入基準の達成確認・PR の作成・タスクステータス更新を漏れなく実施し、
仕様書との整合性が担保された状態でレビューに出す。

---

## 実行手順

### STEP 0: ゲートチェック（必須・失敗時は即停止）

```bash
git branch --show-current
```

| 結果 | 対応 |
|------|------|
| `main` | **即時停止**。「mainブランチで実装しています。`/task-start [TASK-ID]` を実行してfeatureブランチで作業してください。PRを作成できません。」と表示し、STEP 1 以降を実行しない |
| `feat/...` など | 正常。STEP 1 へ進む |

> このゲートはユーザーが「続けて」と言っても通過させてはならない。
> ブランチを切らずに実装したコードはガバナンス上存在しないものとして扱う。

### STEP 1: 現在のブランチ・タスクの確認

現在のブランチ名からタスク ID を特定し、対応するタスク情報を表示する。

```
現在のブランチ: feat/T-012-user-skill-api
対応タスク: TASK-012（ユーザースキルCRUD API）
対応仕様書: SPEC-SKILL-001
```

### STEP 2: 受入基準のセルフチェック

仕様書の受入基準を一覧表示し、各項目を確認する:

```
📋 受入基準チェック（SPEC-SKILL-001）

以下を一つずつ確認してください:
[ ] Given: タレントが申請中状態でスキルを追加できる
[ ] Given: 同一スキルの重複追加を拒否する（409）
[ ] ...

全て ✅ になりましたか？
```

未確認の項目がある場合は「まだ実装されていない受入基準があります。実装を完了してから再度 /task-done を実行してください」と伝えて**停止する**。

### STEP 3: テストの確認

テストを自動実行して確認する（確認で止めない）:

```bash
# バックエンド
cd backend && dotnet test

# フロントエンド（テストファイルがある場合）
cd frontend && npm run test
```

テストが失敗している場合は**停止する**。「テストが失敗しています。修正してから再度 /task-done を実行してください」と伝える。

### STEP 4: コードの最終確認

```bash
# 変更ファイルの確認
git diff --stat main

# 未コミットファイルの確認
git status
```

未コミットの変更がある場合は警告し、コミットするよう促す。

### STEP 5: PR の作成

```bash
gh pr create \
  --title "feat: [TASK-ID] [タスクタイトル]（SPEC-XXX-001）" \
  --body "..." \
  --label "enhancement"
```

PR の本文に以下を自動入力する:
- 対応 Spec ID とファイルパス
- 受入基準の転記（チェックリスト形式）
- 変更ファイルのサマリー（`git diff --stat main` の結果）
- テスト実施の記録（テスト件数・全通過）

内容を表示してユーザーに確認してから実行する。

### STEP 6: レビュアーの設定

CODEOWNERS の設定に基づいてレビュアーを確認する。
ソロ開発の場合はスキップしてよい。

### STEP 7: タスクステータスの自動更新

確認なしに `tasks/task-list.md` の該当タスクを「進行中」→「✅ done」に更新する。

### STEP 8: 完了報告

```
✅ PR 作成完了

PR: https://github.com/[org]/[repo]/pull/[番号]
ブランチ: feat/T-012-user-skill-api → main
テスト: 85件 全通過

次のアクション:
  レビュー承認後に CI が通過したらマージできます
  /task-board でタスクの進捗を確認できます
  次のタスクは /task-start [TASK-ID] で開始してください
```

---

## 注意事項

- STEP 0 のゲートはいかなる場合も省略・バイパスしない
- テストが通過していない状態でPRを出さない
- 受入基準を全て確認してからPRを出す
- 仕様書に書いていない機能を追加していないか確認する
