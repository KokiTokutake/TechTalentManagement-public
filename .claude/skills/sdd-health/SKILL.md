# /sdd-health — SDD 遵守状況の健全性チェック

**使う場面**: 全工程。スプリント開始前・リリース前・定期チェックとして使う。SDD のルールが守られているか診断する。

---

## 目的

プロジェクト全体の SDD 遵守状況を自動診断し、問題点と改善アクションをスコア付きで表示する。
「仕様書ファースト」の習慣が定着しているかを可視化する。

---

## 実行手順

### STEP 1: ファイル・設定の読み込み

以下を確認する:
- `.constitution/Constitution.md`
- `docs/spec/` 配下の全仕様書
- `tasks/task-list.md`
- `.github/CODEOWNERS`
- `.github/workflows/ci.yml`
- `CLAUDE.md`

### STEP 2: 各カテゴリの診断

**カテゴリ1: Constitution 設定（20点）**
```
[ ] Constitution.md が存在する（5点）
[ ] 必須セクションが全て揃っている（5点）
[ ] 用語集が5語以上定義されている（5点）
[ ] 変更管理ルールに承認者が明記されている（5点）
```

**カテゴリ2: 仕様書管理（25点）**
```
[ ] docs/spec/ に仕様書が1件以上ある（5点）
[ ] 全仕様書に Spec ID が付与されている（5点）
[ ] 全仕様書にステータスが記載されている（5点）
[ ] approved 仕様書の受入基準が GWT 形式または明確な条件で書かれている（10点）
```

**カテゴリ3: GitHub 設定（25点）**
```
[ ] Branch Protection が設定されている（確認方法を案内する）（10点）
[ ] CODEOWNERS が設定されている（5点）
[ ] PR テンプレートが存在する（5点）
[ ] Issue テンプレートが存在する（5点）
```

**カテゴリ4: CI/CD 自動化（15点）**
```
[ ] ci.yml が存在する（5点）
[ ] 仕様書フォーマットチェックが設定されている（5点）
[ ] 自動テストが設定されている（5点）
```

**カテゴリ5: 実装プロセス（15点）**
```
[ ] CLAUDE.md が存在し、コーディングルールが記載されている（5点）
[ ] tasks/task-list.md が存在する（5点）
[ ] ai-workflow.md が存在する（5点）
```

### STEP 3: 健全性レポートの出力

```markdown
## 🏥 SDD 健全性チェック（YYYY-MM-DD）

### 総合スコア: 78 / 100 ★★★★☆

| カテゴリ | スコア | 状態 |
|---------|--------|------|
| Constitution 設定 | 15/20 | ⚠️ |
| 仕様書管理 | 20/25 | ⚠️ |
| GitHub 設定 | 25/25 | ✅ |
| CI/CD 自動化 | 10/15 | ⚠️ |
| 実装プロセス | 8/15  | ⚠️ |

### ❌ 即対応が必要（-10点以上）
なし

### ⚠️ 改善推奨
1. Constitution.md の用語集が3語しかない → 5語以上に増やす（/charter-review）
2. SPEC-AUTH-002 のステータスが未設定 → draft/review/approved を設定する
3. CLAUDE.md のコーディングルールが未記入 → 記入する

### ✅ 良好な点
- Branch Protection, CODEOWNERS, PR/Issue テンプレートは設定済み
- CI パイプラインが稼働している

### 推奨アクション
1. /charter-review  → Constitution.md を改善（推定15分）
2. /spec-list       → 仕様書のステータスを確認・更新
3. CLAUDE.md を編集 → コーディングルールを記入
```

### STEP 4: 過去との比較（2回目以降）

前回のチェック結果が保存されている場合は比較して表示する:

```
📈 前回比較（前回: 65点 → 今回: 78点）
  +13点改善! Constitution.md と GitHub 設定の整備が効果的でした。
```

### STEP 5: 結果の保存（任意）

「チェック結果を保存しますか？」と確認し、保存する場合は `docs/guides/` に記録する。

---

## ヘルススコアの目安

| スコア | 状態 | 意味 |
|--------|------|------|
| 90〜100 | 🟢 優秀 | SDD が完全に定着している |
| 70〜89 | 🟡 良好 | 概ね定着。細部を改善中 |
| 50〜69 | 🟠 要改善 | 基本設定は完了。プロセス定着が課題 |
| 〜49 | 🔴 要緊急対応 | 基本設定から見直しが必要 |
