# /release-prep — リリース準備・リリースノート生成

**使う場面**: 工程7（移行・運用）。PO サインオフ後、本番デプロイの準備をするとき。

---

## 目的

リリースノートの自動生成・デプロイチェックリストの確認・リリースタグの作成を行い、
安全なリリースのための準備を整える。

---

## 実行手順

### STEP 1: リリース前提条件の確認

```
以下を確認します:
[ ] acceptance-checklist.md に PO のサインオフがある
[ ] CI が全て通過している
[ ] main ブランチが最新状態である
[ ] ステージング環境での動作確認が完了している

全て ✅ ですか？
```

未確認の項目がある場合は「先に確認してください」と警告して止める。

### STEP 2: リリース情報の収集

```
質問:
- バージョン番号は何にしますか？（例: v1.2.0）
  破壊的変更あり → メジャーバージョン（v2.0.0）
  機能追加あり   → マイナーバージョン（v1.2.0）
  バグ修正のみ   → パッチバージョン（v1.2.1）
- リリース担当者の GitHub ハンドル: @xxx
```

### STEP 3: リリースノートの自動生成

マージ済みの PR と仕様書をもとにリリースノートを生成する。

```bash
# マージ済みPRの取得
gh pr list --state merged --base main --json number,title,labels
```

`docs/guides/release-notes.md` テンプレートに従って生成する:

```markdown
## v1.2.0 — YYYY-MM-DD

### 概要
ログイン機能とユーザープロフィール管理機能を追加しました。

### 新機能
- **ログイン機能** (`SPEC-AUTH-001`): メールアドレスとパスワードでログインできます。
- **プロフィール編集** (`SPEC-USER-001`): プロフィール写真・自己紹介を編集できます。

### 改善
- 読み込み速度を約30%改善しました。

### バグ修正
- **ページ遷移時のチラつき** (`#42`): ローディング中の表示を修正しました。
```

ユーザーに確認して修正してもらう。

### STEP 4: デプロイチェックリスト

`docs/guides/operation-runbook.md` を参照してデプロイ手順を表示する:

```
📋 デプロイチェックリスト（v1.2.0）

事前確認:
[ ] DB マイグレーションスクリプトの準備
[ ] 環境変数の追加・変更の確認
[ ] 依存サービスへの影響確認
[ ] ロールバック手順の確認

デプロイ手順:
[ ] ステージングでの最終確認（完了済み）
[ ] 本番デプロイ開始時間の周知
[ ] GitHub Actions "Deploy to Production" の実行
[ ] ヘルスチェックエンドポイントの確認
[ ] 監視ダッシュボードのエラー率確認（5分間）

リリース後:
[ ] リリースノートの公開
[ ] ステークホルダーへの通知
```

### STEP 5: Git タグとGitHub Release の作成

```bash
git tag -a v1.2.0 -m "Release v1.2.0"
git push origin v1.2.0

gh release create v1.2.0 \
  --title "v1.2.0 — ログイン機能・プロフィール編集" \
  --notes "[リリースノート内容]"
```

「実行しますか？」と確認してから実行する。
