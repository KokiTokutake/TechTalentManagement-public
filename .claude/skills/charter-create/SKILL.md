# /charter-create — プロジェクト憲章（Constitution.md）の対話型作成

**使う場面**: 工程1（原則決定）。プロジェクト憲章を初めて作成するとき、または大幅改訂するとき。

---

## 目的

チーム全員が合意できるプロジェクト憲章（Constitution.md）を、対話型で一項目ずつ丁寧に作成する。
曖昧な表現や抜け漏れを防ぎ、後の全工程の判断基準となる文書を完成させる。

---

## 実行手順

`.constitution/Constitution.md` テンプレートを参照しながら、以下の各セクションをユーザーと対話して埋める。

### セクション 1: プロジェクト概要

```
質問:
- このプロジェクトで何を達成したいですか？（Why）
- 何を作りますか？（What）
- 誰のためですか？（対象ユーザー）
- いつまでに何をリリースしますか？（スコープ・期限）
```

ユーザーの回答をもとに「概要」「目的」「対象ユーザー」「スコープ（含む / 含まない）」を記述する。

### セクション 2: 基本原則と制約

```
質問:
- 開発において絶対に守るべきルールは何ですか？
- 使ってはいけない技術・手法はありますか？
- セキュリティ・コンプライアンス上の制約はありますか？
- パフォーマンス要件はありますか？
```

### セクション 3: ステークホルダーと責任

ユーザーに関係者の役割を確認して責任マトリクスを作成する:

```
確認する役割:
- プロダクトオーナー（仕様の最終決定者）
- テックリード（技術的判断の最終決定者）
- 開発チームメンバー
- QA・テスター
- 経営層（スコープ・予算承認者）
```

### セクション 4: 変更管理ルール

```
質問:
- 仕様書の変更には誰の承認が必要ですか？
- 憲章の変更には誰が合意する必要がありますか？
- 緊急の変更はどのように判断しますか？
```

変更の大きさ（マイナー / スモール / メジャー / 憲章変更）と必要承認者の表を生成する。

### セクション 5: 用語集（ユビキタス言語）

```
質問:
- このプロジェクト固有の専門用語はありますか？
- 業界用語で定義が必要なものはありますか？
- 同じ概念に複数の呼び方がある場合、どれを正式名称にしますか？
```

最低 5〜10 語の用語集を作成する。

### 最終確認

全セクションを記述したら全文を表示し:
- 「このまま保存してよいですか？」と確認する
- 「修正したい箇所はありますか？」と確認する
- OKであれば `git add` と `git commit -m "add: Constitution.md 初版を作成"` を提案する
