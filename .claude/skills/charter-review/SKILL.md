# /charter-review — Constitution.md のレビュー・品質確認

**使う場面**: 工程1（原則決定）。Constitution.md を作成・更新したあと、チームで合意する前の品質確認。

---

## 目的

Constitution.md が「全工程の判断基準」として機能するために必要な5つの観点でレビューし、
具体的な改善点をリストアップする。

---

## 実行手順

### STEP 1: ファイル読み込み

`.constitution/Constitution.md` を読み込む。
ファイルが存在しない場合は「先に `/charter-create` を実行してください」と案内して終了する。

### STEP 2: 5観点レビュー

以下の各観点で評価し、問題点を具体的に指摘する（良い点も示す）。

**観点1: 完全性**
必須セクションがすべて存在するか確認する:
- [ ] プロジェクト概要（目的・スコープ）
- [ ] 基本原則と制約
- [ ] ステークホルダーと責任
- [ ] 変更管理ルール（承認者・プロセス）
- [ ] 用語集（最低5語）
- [ ] 変更履歴

**観点2: 明確性**
- 曖昧な表現（「なるべく」「できれば」「適切に」）を検出して指摘する
- 数値で表現できる項目（パフォーマンス・可用性など）が定性的なままになっていないか確認する

**観点3: 一貫性**
- 同じ概念に複数の名称が使われていないか確認する
- 用語集に定義された用語が本文で一貫して使われているか確認する

**観点4: 実行可能性**
- 変更管理ルールが現実の体制で機能するか確認する
- 承認者として指定された役割が明確に定義されているか確認する

**観点5: 将来性**
- スコープが過度に固定されていないか確認する（変更の余地があるか）
- 「含まない（スコープ外）」が明記されているか確認する

### STEP 3: レポート出力

以下の形式でレポートを出力する:

```markdown
## Constitution.md レビュー結果

### 総合評価: ★★★☆☆（5段階）

### ✅ 良い点
- ...

### ⚠️ 改善が必要な点
| 優先度 | 観点 | 問題 | 改善案 |
|--------|------|------|--------|
| High   | 完全性 | 変更管理ルールの承認者が未記載 | 「仕様変更は PO + TL の両承認が必要」と明記 |
...

### 📋 チェックリスト（合意前確認）
- [ ] 全ステークホルダーがレビューした
- [ ] 全員が内容に合意した
- [ ] Git にコミット・プッシュ済み
```

### STEP 4: 修正支援

「改善点を修正しますか？」と確認し、「はい」であれば指摘した箇所を具体的に書き直す。

---

## 注意事項

- Constitution.md は「生きたドキュメント」なので完璧を求めすぎない
- 初版は2〜3ページで十分。運用しながら育てる
- レビュー後のコミットメッセージ提案: `update: Constitution.md レビューによる改善`
