# /retro-run — レトロスペクティブの実施

**使う場面**: 工程7（運用）。スプリント・リリース終了後の振り返り。次のサイクルにフィードバックを引き継ぐ。

---

## 目的

KPT 形式でスプリントを振り返り、`docs/guides/retrospective.md` に記録し、
次サイクルの仕様書改善につながるアクションアイテムを作成する。

---

## 実行手順

### STEP 1: 振り返りの基本情報を収集

```
質問:
- 対象期間・スプリント名は？（例: Sprint 3 / v1.2.0）
- ファシリテーターは誰ですか？（@handle）
- 参加者は誰ですか？（@handle1, @handle2）
- 実施日: 今日（YYYY-MM-DD）
```

### STEP 2: 定量メトリクスの収集

`tasks/task-list.md` と GitHub の情報をもとに数値を集める。
わからない場合はユーザーに入力してもらう:

```
以下の実績値を教えてください（または "調べる" と言えば確認します）:

- 完了タスク数（SP）: ?
- バグ発生件数（High以上）: ?
- PR レビュー時間（平均）: ?
- 仕様変更回数: ?
- CI 通過率: ?
```

SDD メトリクスも確認する:
```
- 仕様書を先に書いた割合: ?%
- PR に受入基準が記載されていた割合: ?%
```

### STEP 3: KPT の実施（対話型）

**Keep（続けること）** を収集する:

```
🟢 Keep — うまくいったこと、続けるべきプラクティスを教えてください

例: 「仕様書を先に書いてからコーディングしたことでレビューの手戻りが減った」
例: 「毎日タスクボードを確認することでブロッカーの発見が早かった」

何か Keep はありますか？（複数ある場合は一つずつ教えてください）
"完了" と言ったら次に進みます
```

**Problem（問題・課題）** を収集する:

```
🔴 Problem — うまくいかなかったこと、改善が必要なことを教えてください

例: 「仕様書のステータス更新を忘れるケースがあった」
例: 「レビュー時間が80分を超えるPRがあった」

何か Problem はありますか？
"完了" と言ったら次に進みます
```

**Try（試すこと）** を収集する:

```
🔵 Try — Problem への対策・次回試したいことを教えてください

各 Problem に対応する Try を一緒に考えます。

Problem: 「仕様書のステータス更新を忘れる」
  Try の案: 「PR テンプレートに仕様書ステータス更新チェックを追加する」
  → この Try を採用しますか？担当者と期限は？
```

### STEP 4: SDD プロセスの評価

各工程の評価（1〜5）をユーザーに確認する:

```
各工程を 1（改善必要）〜 5（非常に良い）で評価してください:

1. 原則決定（Constitution）: ?
2. 企画・要件定義（Specify）: ?
3. 設計計画（Plan）: ?
4. タスク分割（Tasks）: ?
5. 実装（Implement）: ?
6. 検証・受入（Verify）: ?
7. 移行・運用（Operation）: ?
```

評価が3以下の工程については「何が問題でしたか？」と深掘りする。

### STEP 5: 次サイクルへのフィードバック

```
次のスプリント/フェーズへの申し送り事項を教えてください:

- 未完了タスクはありますか？（理由も）
- 技術的負債はありますか？
- 次担当者が知るべき注意事項はありますか？
```

### STEP 6: アクションアイテムの確定

全ての Try を確認し、アクションアイテム一覧を作成する:

```markdown
## アクションアイテム

| # | アクション | 担当 | 期限 | ステータス |
|---|-----------|------|------|----------|
| 1 | PR テンプレートに仕様書ステータス確認チェックを追加 | @tl | YYYY-MM-DD | 未着手 |
| 2 | /impl-check をタスク完了前の必須ステップとしてルール化 | @tl | YYYY-MM-DD | 未着手 |
```

「このアクションアイテムを GitHub Issues として作成しますか？」と確認する。

### STEP 7: retrospective.md への保存

全内容を `docs/guides/retrospective.md` テンプレートに整形して保存する。

---

## 出力ファイル

- `docs/guides/retrospective.md`（追記）
- GitHub Issues（アクションアイテム、任意）
