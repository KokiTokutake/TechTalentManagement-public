# /impl-guide — 実装ガイダンス（仕様書・設計書の読み込み）

**使う場面**: 工程5（実装）。コーディングを開始するとき、または実装方針を確認したいとき。

---

## 目的

現在のタスクに関連する仕様書・設計書・CLAUDE.md を読み込み、
「何を・どのように実装すべきか」を明確にした上でコーディングを支援する。

---

## 実行手順

### STEP 1: 現在のコンテキストの確認

現在のブランチからタスク・仕様書を特定する:

```bash
git branch --show-current
# → feat/42-login-api-endpoint
```

タスクが特定できない場合は「どのタスクを実装していますか？（TASK ID または仕様書の Spec ID）」と確認する。

### STEP 2: 関連ドキュメントの一括読み込み

以下をすべて読み込む:
- 対応する仕様書（Spec ID から `docs/spec/` を検索）
- 関連する設計書（`docs/design/`）
- `CLAUDE.md`（コーディングルール・ディレクトリ構造）
- `.constitution/Constitution.md`（制約・原則）

### STEP 3: 実装方針のサマリー表示

```markdown
## 🔨 実装ガイダンス: TASK-001（SPEC-AUTH-001）

### 実装すること
1. POST /api/auth/login エンドポイントの作成
2. メールアドレス + パスワードの認証処理
3. JWT トークン発行（有効期限: 24時間）
4. ログイン失敗カウンターの管理（5回でロック）

### 実装しないこと（スコープ外）
- ソーシャルログイン（SPEC-AUTH-002 で別途対応）
- パスワードリセット機能

### 実装の手順（推奨順序）
1. UserRepository: findByEmail() の実装
2. AuthService: validateCredentials() の実装
3. AuthService: generateToken() の実装
4. AuthController: POST /login のルーティング
5. 単体テストの作成
6. 統合テストの作成

### コーディングルール（CLAUDE.md より）
- エラーハンドリング: Result 型を使用する
- パスワード: bcrypt でハッシュ化（saltRounds: 12）
- JWT: HS256 アルゴリズム、環境変数 JWT_SECRET を使用
- 命名: キャメルケース（関数）/ パスカルケース（クラス）

### ✅ 完了条件（受入基準）
- [ ] 正しい認証情報で 200 + JWT が返る
- [ ] 誤ったパスワードで 401 が返る
- [ ] 5回失敗でアカウントロック（HTTP 423）
- [ ] 各受入基準に対応するテストが通過する
```

### STEP 4: コード生成支援

「実装を開始しますか？」と確認し、「はい」の場合:

1. 実装対象のファイルパスを確認する
2. 仕様書・設計書の内容に基づいてコードを生成する
3. 生成したコードをユーザーが確認・修正する
4. テストコードも一緒に生成する

### STEP 5: Human-in-the-Loop の確認

生成したコードを提示する際に必ず確認する:
```
⚠️ AI が生成したコードです。以下を確認してください:
- 受入基準を満たしているか？
- セキュリティの問題はないか？
- コーディングルールに従っているか？
- 仕様書に書かれていない機能を追加していないか？

確認できたら実装を進めてください。
```

---

## 注意事項

- AI が提案したコードをそのままコミットしない。必ず人間がレビューする（Human-in-the-Loop）
- 仕様書に書かれていない機能を追加しない
- 実装中に仕様の不備を発見したら、コードを変更する前に `/spec-change` を実行する
