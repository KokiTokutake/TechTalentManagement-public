SDD ハーネス — クイックスタートガイド

新規プロジェクトへの仕様駆動開発（Spec-Driven Development）導入手順

⏱ 初期セットアップ 30〜60分 31スキル同梱 Claude Code 必須 GitHub CLI 必須

SDD ハーネスとは

仕様駆動開発（SDD）は「コードより先に仕様を書く」開発手法です。本ハーネスはその実践に必要な テンプレート・Claude Code スキル・PM ツール・Hooks ガード を一式パッケージ化したものです。 新規プロジェクトにコピーするだけで SDD ワークフローがすぐに使えます。

Spec-as-Code
仕様書を Markdown で Git 管理。唯一の信頼できる情報源
🤖

前提条件

ツール 区分 確認コマンド 備考
Claude Code 必須 claude --version スキル実行・AI コードレビューに使用
Git 必須 git --version バージョン管理・ブランチ保護
GitHub CLI (gh) 必須 gh auth status PR 作成・Issue 連携・PR レビュー学習に使用
Python 3 必須 python3 --version Hooks スクリプトの JSON 解析に使用
Node.js / npm 推奨 node --version Playwright テスト自動化に使用
GitHub リポジトリ 必須 gh repo view PR レビュー・Branch Protection の前提
macOS / Linux: bash が標準で使えます。Windows: Git Bash または WSL2 を使用してください。PowerShell 環境では hooks の bash スクリプトが動作しません。

インストール手順

1
ハーネスをプロジェクトにコピーする
SDD ハーネスリポジトリをクローンし、templates/ の中身をプロジェクトルートにコピーします。
# ハーネスを取得（初回のみ） git clone https://github.com/KokiTokutake/SpecDrivenDevelopmentHarness.git ~/sdd-harness # プロジェクトルートに移動してテンプレートをコピー cd /your/project/root cp -r ~/sdd-harness/templates/. . # hooks に実行権限を付与 chmod +x .claude/hooks/*.sh
注意: コピー先に同名ファイルが存在する場合は上書きされます。git status で変更を確認してください。
2
Claude Code でプロジェクトを開き /sdd-start を実行する
プロジェクトルートで Claude Code を起動し、セットアップウィザードを実行します。所要時間：約15〜30分。
# プロジェクトルートで Claude Code を起動 claude # Claude Code のプロンプトで実行 /sdd-start
ウィザードが実施すること
  • ① プロジェクト基本情報の収集（名前・技術スタック・チーム規模）
  • ② .constitution/Constitution.md の初版生成・確認
  • ③ CLAUDE.md の技術スタック・コマンドを設定
  • ④ .claude/hooks/ の存在確認・セットアップ
  • ⑤ GitHub Branch Protection の設定チェックリスト表示
3
GitHub Branch Protection を設定する
main ブランチを保護し、仕様書なしの直接コミットを防ぎます。
# GitHub CLI で設定（要 admin 権限） gh api repos/{owner}/{repo}/branches/main/protection \ --method PUT \ --field 'required_pull_request_reviews={"required_approving_review_count":1}' \ --field 'enforce_admins=true'
GitHub の Settings → Branches → Branch protection rules からGUI でも設定できます。
4
最初の仕様書を作成して動作確認する
小さな機能の仕様書を1本書いて、スキルが正しく動くか確認します。
# 仕様書の作成（対話型ウィザード） /spec-write # 仕様書のレビュー /spec-review
完了の確認: docs/spec/ に仕様書ファイルが生成され、status: approved になれば導入完了です。
5
PM ツールをブラウザで開く（任意）
スプリント・タスク・KPI をブラウザで管理します。ファイルをダブルクリックするだけで起動します。
# ブラウザで PM ツールを開く open tools/pm/index.html # macOS start tools/pm/index.html # Windows
PM ツールの「設定」タブからプロジェクトフォルダと接続すると tasks/pm-data.json と自動同期します（Chrome / Edge のみ）。

コピー後のディレクトリ構成

project/ ├── .claude/ ← ハーネスが追加（Claude Code 設定） │ ├── settings.json ← Hooks 設定（PreToolUse ガード） │ ├── hooks/ │ │ ├── guard-dangerous-bash.sh ← 危険操作ブロック │ │ └── guard-spec-edit.sh ← 仕様書無断編集ブロック │ └── skills/ ← 31スキル（/コマンドで呼び出し） │ ├── sdd-start/SKILL.md │ ├── spec-write/SKILL.md │ └── ... （29スキル） ├── .constitution/ │ └── Constitution.md ← /sdd-start で生成するプロジェクト憲章 ├── docs/ │ ├── spec/ ← 仕様書 (Spec-as-Code) │ ├── design/ ← 設計ドキュメント │ └── guides/ │ └── review-patterns.md ← /review-learn でPRから学習・蓄積 ├── tasks/ ← タスク一覧・PM ツールデータ ├── tests/ │ └── e2e/ ← /test-write で自動生成する Playwright テスト ├── tools/ │ └── pm/ ← ブラウザ PM ツール（index.html） └── CLAUDE.md ← /sdd-start で設定するプロジェクト固有ルール
緑色のパス がハーネスによって追加されるファイル/ディレクトリです。既存ファイルには影響しません（同名ファイルのみ要確認）。

自動保護ガード（Hooks）

.claude/settings.json に設定された hooks は、Claude Code がツールを実行する前に自動的に発動します。

🛡️ guard-dangerous-bash.sh — 危険コマンドのブロック
操作パターン判定
rm -rf / rm -rf *ブロック
git push --force to main/masterブロック
git reset --hardブロック
git clean -fdブロック
git checkout -- . / git restore .ブロック
DROP TABLE / DROP DATABASEブロック
git push --force to feature branch警告
通常のコマンド許可
📄 guard-spec-edit.sh — 仕様書無断編集のブロック
条件判定
docs/spec/ 内のファイル
かつ status: approved
かつ 実装タスクが進行中 		ブロック
/spec-change ワークフロー経由
（status を under_review に変更） 		許可
status: draft / under_review の仕様書許可
実装タスクが未開始の場合許可
docs/spec/ 以外のファイル許可
→ ブロック時は /spec-change の実行を案内します
