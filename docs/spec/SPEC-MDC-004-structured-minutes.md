## 1. 背景・目的（Why）

### 1.1 解決する問題

現状のMDCセッション（SPEC-MDC-001）には議事録フィールドがあるが、フリーテキストのため「何が決まったか」「誰が何をいつまでにやるか」が構造化されていない。前回の委員会決定事項の追跡ができず、アクションアイテムの未実施が発覚しにくい。

### 1.2 ビジネス価値

- 決定事項とアクションアイテムを構造化して記録することで、前回委員会決定事項のフォローアップを確実に実施できる
- 委員会の意思決定履歴が検索・参照可能になり、組織の人事方針の継続性が向上する
- タレント別の決定事項一覧をタレントプロファイル（SPEC-MDC-003）に表示することで、育成の一貫性を担保する

### 1.3 対象ユーザー

| ユーザー | 権限 |
|---------|------|
| 管理者（人事評価チーム）/ Senior / Executive | 議事録・決定事項・アクションアイテムの作成・編集・確認 |
| 管理職 | 自部門に関係するアクションアイテムの閲覧・完了報告 |
| 上長 | 配下タレントに関するアクションアイテムの閲覧・完了報告 |

## 2. 要件（What）

### REQ-01: 決定事項の構造化記録 【Must】

MDCセッションの議事録に、以下を構造化して登録できる：
- 決定事項タイプ（重点管理指定/解除・育成方針変更・異動検討・その他）
- 決定内容テキスト
- 対象タレント（0〜複数）
- 決定日

### REQ-02: アクションアイテムの登録と追跡 【Must】

各決定事項に対して、アクションアイテムを複数登録できる：
- 内容（テキスト）
- 担当者（システムユーザーから選択）
- 期限
- ステータス（未着手・進行中・完了・キャンセル）

アクションアイテムは次回MDCセッション開始時に自動的に前回セッションからの未完了一覧を表示する。

### REQ-03: 未完了アクションの自動引き継ぎ表示 【Must】

新規MDCセッション作成時に、前回セッションの未完了アクションアイテムを「前回の積み残し」セクションに自動表示する。委員が完了確認またはキャンセルを選択してから次のアジェンダに進む。

### REQ-04: タレント別決定事項履歴 【Should】

特定タレントに関する全MDC決定事項を時系列で一覧表示できる（タレントプロファイル画面に埋め込み）。

### REQ-05: アクションアイテムのダッシュボード 【Should】

担当者ごとの未完了アクションアイテム一覧を表示するダッシュボードウィジェットを提供する。期限超過のアイテムは警告色で表示する。

### REQ-06: 議事録のエクスポート 【Could】

MDCセッションの構造化議事録（決定事項＋アクションアイテム）をPDFまたはWordで出力する。

---

## 3. スコープ外（作らないこと）

- 議事録の自動生成（AI文字起こし・要約）
- 外部タスク管理ツール（Jira・Asana等）との同期
- 電子署名・承認ワークフロー

## 4. 受入基準

### REQ-01: 決定事項の構造化記録

**AC-01-01: 決定事項の登録**
- Given: 人材開発委員がMDCセッションの議事録画面を開いている
- When: 決定タイプ「重点管理指定」・対象タレント「田中太郎」・決定内容「Q3から集中育成対象に指定」を入力して追加する
- Then: 決定事項が一覧に追加され、対象タレントのプロファイルの「MDC決定履歴」にも反映される

**AC-01-02: 複数タレントへの関連付け**
- Given: 決定事項登録フォームが表示されている
- When: 対象タレントに2名を選択して登録する
- Then: 決定事項が2名それぞれのタレントに関連付けられ、両方のプロファイルに表示される

### REQ-02: アクションアイテムの登録と追跡

**AC-02-01: アクションアイテムの追加**
- Given: 決定事項が登録されている
- When: アクションアイテム「田中さんとの月次1on1を設定する」・担当者「鈴木マネージャー」・期限「2026-06-30」を入力して追加する
- Then: アクションアイテムがステータス「未着手」で登録される

**AC-02-02: ステータス更新**
- Given: 担当者の上長がアクションアイテム一覧を表示している
- When: 担当アイテムのステータスを「完了」に変更する
- Then: ステータスが「完了」に更新され、完了日時が記録される

**AC-02-03: 期限超過の警告**
- Given: 期限が過去日付のアクションアイテムが存在する
- When: アクションアイテム一覧を開く
- Then: 期限超過アイテムが警告色（赤）で表示され、一覧の上部に「期限超過 N件」バッジが表示される

### REQ-03: 未完了アクションの自動引き継ぎ

**AC-03-01: 前回積み残し表示**
- Given: 前回のMDCセッションに未完了アクションアイテムが3件ある
- When: 新規MDCセッションを作成して議事録画面を開く
- Then: 「前回の積み残し（3件）」セクションが自動表示され、各アイテムの内容・担当者・期限が確認できる

**AC-03-02: 積み残しの確認操作**
- Given: 前回積み残しセクションが表示されている
- When: アイテムに「完了」または「キャンセル」をクリックする
- Then: ステータスが更新され、確認済みアイテムは折りたたまれる

### REQ-04: タレント別決定事項履歴

**AC-04-01: タレントプロファイルへの表示**
- Given: タレントAに対する過去3回のMDC決定事項が存在する
- When: タレントAのプロファイル画面を開く
- Then: 「MDC決定履歴」セクションに、決定日・決定タイプ・決定内容が時系列（新しい順）で表示される

### REQ-05: アクションアイテムダッシュボード

**AC-05-01: 担当者別表示**
- Given: 人材開発委員が自分に割り当てられた未完了アクションアイテムが5件ある
- When: MDCダッシュボードを開く
- Then: 「自分のアクションアイテム（5件）」ウィジェットが表示され、期限順にリストされる

---

> **SPEC-MDC-001との共存**: SPEC-MDC-001の`CommitteeSession.Minutes`（フリーテキスト）は引き続き保持し、本仕様の`MdcDecision`・`MdcActionItem`を補完的に追加する。セッション作成時はMinutesへの自由記述と決定事項の構造化入力を並列で利用できる。

## 5. データモデル（概要）

```
MdcDecision {
  id: string (ULID)
  sessionId: string → MdcSession.id
  decisionType: enum { KeyPersonAssign, KeyPersonRemove, DevelopmentPolicyChange, TransferConsideration, Other }
  content: string (max: 2000)
  decidedAt: date
  createdBy: string → User.id
  createdAt: datetime
  updatedAt: datetime
}

MdcDecisionTalent {
  decisionId: string → MdcDecision.id  (PK複合)
  talentId: string → User.id           (PK複合)
}

MdcActionItem {
  id: string (ULID)
  decisionId: string | null → MdcDecision.id  # 決定事項との紐付け（任意）
  sessionId: string → MdcSession.id           # セッション直接紐付けも可
  description: string (max: 500)
  assigneeId: string → User.id
  dueDate: date | null  # 期限未定の場合は null 可
  status: enum { NotStarted, InProgress, Done, Cancelled }
  completedAt: datetime | null
  createdAt: datetime
  updatedAt: datetime
}
```

## 6. APIエンドポイント（概要）

```
GET  /api/mdc-sessions/{sessionId}/decisions         → 決定事項一覧取得（MDC/Senior）
POST /api/mdc-sessions/{sessionId}/decisions         → 決定事項作成（MDC）
PUT  /api/mdc-decisions/{id}                         → 決定事項更新（MDC）

POST /api/mdc-decisions/{decisionId}/action-items    → アクションアイテム追加（MDC）
GET  /api/mdc-sessions/{sessionId}/action-items      → セッション内AIリスト取得
PATCH /api/mdc-action-items/{id}/status              → ステータス更新（MDC/Manager）

GET  /api/talents/{talentId}/mdc-decisions           → タレント別決定履歴（MDC/Senior/Manager）
GET  /api/users/{userId}/action-items?status=pending → 担当者別AI一覧（MDC/Senior/Manager）
```

## 7. 非機能要件

| 項目 | 要件 |
|------|------|
| パフォーマンス | 決定事項・アクションアイテムの一覧取得を2秒以内に返す |
| セキュリティ | MDC決定事項は人材開発委員・シニアマネージャー・関係する上長のみ閲覧可能 |
| データ保持 | MDC決定事項・議事録データは5年間保持する |
| 監査ログ | 決定事項の作成・更新・アクションアイテムのステータス変更はAuditLogに記録 |
