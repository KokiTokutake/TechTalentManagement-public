# SPEC-ENHANCE-001: リサーチに基づく機能改善仕様

**Spec ID**: SPEC-ENHANCE-001  
**Status**: reference（調査まとめ資料。各機能は SPEC-CAREER-002, SPEC-EVAL-002, SPEC-MDC-002〜005, SPEC-SKILL-002 として個別仕様書化済み）  
**優先度**: Medium〜High（項目ごとに個別設定）  
**関連Spec**: SPEC-MDC-001, SPEC-CAREER-001, SPEC-SKILL-001, SPEC-EVAL-001  
**調査対象**: リクルート社のWill-Can-Mustフレームワーク、人材開発委員会（MDC）の実務、ITSS、iCD、MBO/OKRの実務

---

## 背景・調査方針

本仕様は以下を参考に、TechTalentManagementシステムの実務適合性を高めるための改善要件をまとめたものである：

- **リクルート社のWill-Can-Must運用実例**（半期更新、1on1連携、Can強み/課題の両面記述）
- **人材開発委員会（MDC）の階層別運営実務**（部レベル・経営レベルの区分、9ボックス、タレントプロファイル）
- **ITSS（ITスキル標準）**（経産省/IPA策定の7段階×11職種）
- **iCD（iコンピテンシディクショナリ）**（テクノロジ/メソドロジ/ビジネスインダストリ/共通の4軸）
- **後継者計画（サクセッションプラン）**（Ready Now / Ready Soon / Mid Term）
- **MBO/OKR**（目標KPI・中間振り返り・フィードバック面談記録）

## Part 1: Will-Can-Must フレームワークの深化

### ENHANCE-1-1: Willの時間軸分割

**現状**: 中長期目標・中期目標・今期の注力テーマの3フィールド（単純テキスト）

**課題**: リクルート実例では「短期（6ヶ月）」と「中期（2〜3年）」を明確に分けて記入する。現行設計は粒度が粗い。

**改善内容**:

```
CareerPlan に以下フィールドを追加:
  - shortTermGoal (string, max:500)    // 6ヶ月以内に達成したいこと
  - midTermGoal   (string, max:1000)   // 1〜3年後のなりたい姿
  - longTermVision(string, max:1000)   // 3〜5年後・将来ビジョン（既存longTermGoalを改名）
  - currentFocus  (string, max:500)    // 今期の注力テーマ（既存フィールド）
  - motivationSource (string, max:500) // やりがいを感じること・大切にしている価値観
```

**画面への反映**:
- キャリアプランのWillセクションに「6ヶ月で実現したいこと」欄を追加
- 「やりがいの源泉」欄を追加（動機付けの可視化）

**受入基準**:
```
Given: タレントがキャリアプラン入力画面を開く
When:  Willセクションを入力する
Then:  「6ヶ月目標」「1〜3年目標」「3〜5年ビジョン」「やりがいの源泉」の4フィールドが入力できる
```

### ENHANCE-1-2: Canの強み・課題の両面記述

**現状**: スキルマップ（Can）は申請→承認のスキルマスター連携のみ。弱みや能力開発課題の記録がない。

**課題**: リクルート実例では「強みの定量的記述」と「克服したい弱み（能力開発課題）」の両方を記入する。弱みの自覚・言語化がないと育成計画の質が下がる。

**改善内容**:

CareerPlan に追加:
```
  - canStrengths  (string, max:1000)   // 強み（定量的記述。例: チームリーダー経験3年）
  - canDevelopment(string, max:1000)   // 能力開発課題（弱み・伸ばしたいスキル）
```

UserSkillに追加:
```
  - selfAssessmentNote (string, max:500) // スキルの定量的根拠メモ
                                         //（例: 業務でTypeScriptを2年使用、コードレビュー月20件）
```

**受入基準**:
```
Given: タレントがキャリアプランのCanセクションを入力する
When:  「強みの根拠」と「能力開発課題」を記入して保存する
Then:  保存が成功し、上長・管理職が閲覧できる
```

---

### ENHANCE-1-3: Mustの定量目標（KPI）フィールド

**現状**: 目標設定は「タイトル + 詳細説明」のみ。KPIの数値目標が記録できない。

**課題**: MBO/OKR実務では「目標値（数値）」と「達成指標（KPI）」が必須。「コードレビュー指摘件数3件以下」のような定量基準がないと達成の判断が主観的になる。

**改善内容**:

Goal に追加:
```
  - targetKpi    (string, max:200, nullable)  // 達成指標（例: バグ発生件数 5件以下/四半期）
  - targetValue  (string, max:100, nullable)  // 目標値（例: 100%、5件以下）
  - measureMethod(string, max:200, nullable)  // 測定方法（例: Redmineチケット集計）
```

**受入基準**:
```
Given: タレントが目標を登録する
When:  「達成指標（KPI）」「目標値」「測定方法」を入力して保存する
Then:  保存が成功し、自己評価時に目標値と実績値を対比表示できる
```

---

### ENHANCE-1-4: 中間振り返り（四半期チェックポイント）

**現状**: 評価サイクルは「目標設定→自己評価→上長評価→確定」の4フェーズのみ。中間確認がない。

**課題**: リクルート実例では「月次1on1（進捗確認）」＋「四半期中間確認（目標妥当性検証・修正）」が組み込まれている。現行は半期末の自己評価まで公式な中間接点がない。

**改善内容**:

新エンティティ `GoalCheckIn` を追加:
```
  GoalCheckIn:
    Id         (Guid)
    GoalId     (Guid, FK→Goals)
    UserId     (Guid, FK→Users)  // 記録者（タレント本人 or 上長）
    CheckedAt  (DateOnly)
    Progress   (int, 0〜100)     // 進捗率（%）
    Comment    (string, max:1000) // 振り返りコメント
    NextActions(string, max:500, nullable) // 次のアクション
    CreatedAt  (DateTimeOffset)
```

**受入基準**:
```
Given: 目標が登録されており、評価期間中である
When:  タレントまたは上長が中間振り返りを登録する
Then:  進捗率・振り返りコメント・次のアクションが保存され、目標カードに最新進捗が表示される
```

## Part 2: スキル評価の精緻化

### ENHANCE-2-1: スキルレベル定義の拡充（ITSSベース）

**現状**: スキルレベルは1〜5の数値のみ。各レベルに「知識あり/学習中/実務可/指導可/エキスパート」のラベルを付けているが、判断基準が曖昧。

**課題**: ITSS（ITスキル標準）では7段階の具体的行動基準が定義されている。「指導可」より詳細な判断基準がないとレベル申請の妥当性が判断しにくい。

**改善内容**:

SkillLevel定義に行動基準を追加（システム設定として管理）:

| Lv | ラベル | 行動基準 |
|----|--------|----------|
| 1 | 知識習得中 | 基礎知識を学習中。業務への単独適用は困難。OJT指導が必要。 |
| 2 | 学習完了・試用段階 | 基本的な知識あり。指導下であれば業務に適用できる。 |
| 3 | 実務可能 | 単独での実務適用が可能。一般的なケースに対応できる。 |
| 4 | 指導可能 | 高難度ケースにも対応でき、後進の指導・レビューができる。 |
| 5 | エキスパート | 社内の標準を自ら定義できる。社外での専門的認知を持つ。 |

さらに SkillItem テーブルに追加:
```
  - itssCategory  (string, nullable)  // ITSS職種分類（マーケ/SE/PM/スペシャリスト等）
  - levelBenchmarks (JSON, nullable)  // 各レベルの具体的行動基準テキスト
```

---

### ENHANCE-2-2: コンピテンシー評価の追加

**現状**: スキル評価はテクニカルスキル（SkillMaster）のみ。ビジネススキル・マネジメントスキルの評価軸がない。

**課題**: iCD（iコンピテンシディクショナリ）では「テクノロジ/メソドロジ/ビジネスインダストリ/共通」の4軸評価を推奨。テクニカルスキルだけではエンジニアの総合的な能力評価が難しい。

**改善内容**:

新カテゴリ「コンピテンシー」をSkillMasterに追加（管理者が設定）:

**テクノロジ軸（システムが提案するデフォルト項目例）**:
- 設計・アーキテクチャ力
- コーディング・実装力
- テスト・品質保証力
- セキュリティ意識・実践
- クラウド・インフラ理解

**メソドロジ軸**:
- プロジェクト管理力
- 問題解決・課題発見力
- ドキュメント作成力
- レビュー・フィードバック力

**共通スキル軸**:
- コミュニケーション力（技術内容の非技術者への説明力）
- 後進育成・OJT指導力
- 自律的な学習継続力
- 当事者意識・主体性

SkillCategory に追加:
```
  - axisType (enum: Technical | Competency | Business)
```

## Part 3: 1on1記録機能の新設

### ENHANCE-3-1: 1on1面談記録

**現状**: キャリアプランに上長コメントを追加できるが、面談記録としての構造がない。

**課題**: リクルート実例では「毎週〜毎月の1on1」がWill-Can-Mustシートと連動する重要なインターフェースである。面談の継続性（前回記録を踏まえた次回面談）がないと育成の連続性が失われる。

**改善内容**:

新エンティティ `OneOnOneMeeting` を追加:
```
  OneOnOneMeeting:
    Id           (Guid)
    TalentId     (Guid, FK→Users)
    ManagerId    (Guid, FK→Users)
    HeldOn       (DateOnly)
    DurationMinutes (int, nullable)
    AgendaItems  (string, max:500, nullable)  // 話したいトピック（事前記入）
    TalentNote   (string, max:2000, nullable) // タレント記録
    ManagerNote  (string, max:2000, nullable) // 上長記録
    ActionItems  (string, max:1000, nullable) // 次のアクションアイテム
    NextMeetingDate (DateOnly, nullable)
    CreatedAt    (DateTimeOffset)
```

**画面**:
- 上長向け: 部下ごとの1on1記録一覧・新規記録入力
- タレント向け: 自分の1on1記録閲覧（マイページに統合）

**受入基準**:
```
Given: 上長が1on1を実施した
When:  1on1記録を登録する
Then:  タレント・上長の記録、アクションアイテム、次回日時が保存される

Given: 上長が新規1on1記録を作成する
When:  前回記録がある
Then:  前回のアクションアイテムが参照表示される
```

## Part 4: 人材開発委員会（MDC）の機能強化

### ENHANCE-4-1: 9ボックス評価の追加

**現状**: MDCサマリーはWill/Can/Mustの情報表示のみ。タレントの「パフォーマンス × ポテンシャル」の2軸評価がない。

**課題**: 人材開発委員会の最重要ツールである9ボックスが未実装。委員会でのタレント分類・施策立案に不可欠。

**改善内容**:

新エンティティ `TalentBoxAssessment` を追加:
```
  TalentBoxAssessment:
    Id              (Guid)
    TalentId        (Guid, FK→Users)
    AssessedBy      (Guid, FK→Users)
    SessionId       (Guid, nullable, FK→CommitteeSessions)  // 委員会セッションとの紐付け
    PerformanceScore (int, 1〜3)   // 1:低 2:中 3:高（パフォーマンス評価）
    PotentialScore   (int, 1〜3)   // 1:低 2:中 3:高（ポテンシャル評価）
    AssessmentNote   (string, max:500, nullable)
    AssessedAt       (DateTimeOffset)
```

9ボックスの各セルに対応する推奨アクション（システム設定として保持）:

| ポテンシャル/パフォーマンス | 低(1) | 中(2) | 高(3) |
|---------------------------|-------|-------|-------|
| **高(3)** | 観察・育成支援が必要 | 育成候補・挑戦機会の付与 | **リーダー候補・重点管理** |
| **中(2)** | 現職強化・再配置検討 | 標準育成・現職継続 | 成長支援・可視化向上 |
| **低(1)** | 配置・適性の見直し | 基礎スキル強化 | パフォーマンス要因を分析 |

**画面**:
- MDCサマリー画面に9ボックスビューを追加
- 各セルをクリックすると該当タレントの一覧を表示
- 委員会セッション記録時に9ボックス評価を入力できる

**受入基準**:
```
Given: 管理職・上位管理職がMDCサマリーを閲覧する
When:  9ボックスビューを開く
Then:  全重点管理人物が「パフォーマンス × ポテンシャル」で分類されてマトリックス表示される

Given: 委員会セッションで参加者が9ボックス評価を入力する
When:  対象タレントの評価スコアを選択して保存する
Then:  セッションと紐付いた形で評価が記録される
```

### ENHANCE-4-2: タレントプロファイル（委員会事前資料）

**現状**: 委員会セッションには議事録・参加者・対象KeyPersonの情報しかない。委員が事前に対象者情報を確認できない。

**課題**: MDC実務では「タレントプロファイル（評価結果・スキルマップ・キャリアプラン・育成計画の集約）」を事前配布して審議の質を高める。

**改善内容**:

新API: `GET /api/mdc/talent-profile/{talentId}` を追加。以下の情報を集約して返す:

```json
{
  "user": { /* 基本情報・役職・上長名 */ },
  "currentPeriodGoals": [ /* 今期目標一覧 */ ],
  "selfEvaluations": [ /* 最新の自己評価 */ ],
  "managerEvaluations": [ /* 最新の上長評価 */ ],
  "approvedSkills": [ /* 承認済みスキル一覧 */ ],
  "careerPlan": { /* 最新のキャリアプラン */ },
  "keyPersonStatus": { /* 重点管理フラグ・指定理由 */ },
  "developmentPlans": [ /* 育成方針履歴 */ ],
  "recentBoxAssessment": { /* 最新9ボックス評価 */ },
  "oneOnOneSummary": { /* 直近3件の1on1記録 */ },
  "sessionHistory": [ /* 過去の委員会登場履歴 */ ]
}
```

**画面**:
- 重点管理人物一覧・委員会セッション画面から「プロファイルを見る」ボタン
- A4印刷対応のタレントプロファイルページ

**受入基準**:
```
Given: 委員会セッション編集画面で対象KeyPersonを選択している
When:  「プロファイルを見る」をクリックする
Then:  対象タレントの評価・スキル・キャリアプラン・育成方針が一画面に集約表示される
```

### ENHANCE-4-3: 委員会議事録の構造化

**現状**: CommitteeSession の Minutes フィールドは単純なテキスト（最大10,000文字）。

**課題**: 委員会の実務では「議題ごとの決定事項」「アクションアイテム（担当者・期限付き）」が重要。自由テキストでは決定事項の追跡ができない。

**改善内容**:

CommitteeSession に追加:
```
  - Objective     (string, max:500, nullable)     // 今回の委員会の目的・テーマ
  - AgendaItems   (JSON, nullable)                 // 議題一覧（構造化）
  - Decisions     (string, max:3000, nullable)     // 決定事項まとめ
  - ActionItems   (JSON, nullable)                 // アクションアイテム（担当者・期限）
  - NextSessionDate (DateOnly, nullable)           // 次回予定日
```

AgendaItems の JSON 構造例:
```json
[
  {
    "order": 1,
    "title": "前回アクションアイテムの確認",
    "status": "completed"
  },
  {
    "order": 2,
    "title": "田中太郎の育成状況レビュー",
    "targetKeyPersonId": "xxx",
    "status": "discussed"
  },
  {
    "order": 3,
    "title": "新規重点管理人物候補の審議",
    "status": "pending"
  }
]
```

ActionItems の JSON 構造例:
```json
[
  {
    "item": "田中太郎のアーキテクト研修申込を手配する",
    "assignee": "山田一郎（上長）",
    "dueDate": "2026-06-30"
  }
]
```

### ENHANCE-4-4: 後継者計画（サクセッションプラン）

**現状**: 重点管理人物（KeyPerson）は指定・解除の2状態のみ。「いつ頃重要ポジションに就けるか」の成熟度が管理できない。

**課題**: 花王等の事例では `Ready Now / Ready Soon（1〜3年）/ Mid Term（3〜5年）` の3段階で後継者候補を管理する。中長期の人材計画に不可欠。

**改善内容**:

KeyPerson に追加:
```
  - SuccessionReadiness (enum, nullable)
      ReadyNow     // 今すぐ重要ポジションに就ける
    | ReadySoon    // 1〜3年で準備できる
    | MidTerm      // 3〜5年で育成が必要

  - TargetPosition (string, max:200, nullable)  // 想定する将来ポジション
  - SuccessionNote (string, max:500, nullable)  // 後継者計画メモ
```

**画面**:
- 重点管理人物一覧に「成熟度」列を追加
- MDCサマリーに後継者マップ（ポジション × 候補者）を追加

**受入基準**:
```
Given: 管理職が重点管理人物の詳細を編集する
When:  後継者成熟度（Ready Now / Ready Soon / Mid Term）と想定ポジションを保存する
Then:  委員会サマリーの後継者マップに反映される
```

## Part 5: 評価フロー・フィードバックの強化

### ENHANCE-5-1: フィードバック面談記録

**現状**: 上長評価完了・確定後のフィードバック面談記録がない。評価結果の「伝達・納得」プロセスがシステム上存在しない。

**課題**: MDC実務の最終ステップは「フィードバック面談（被評価者への内容伝達・次期目標すり合わせ）」。これが記録されないと評価の納得度・改善効果が追跡できない。

**改善内容**:

新エンティティ `FeedbackMeeting` を追加:
```
  FeedbackMeeting:
    Id             (Guid)
    PeriodId       (Guid, FK→EvaluationPeriods)
    TalentId       (Guid, FK→Users)
    ManagerId      (Guid, FK→Users)
    HeldOn         (DateOnly)
    TalentReaction (string, max:1000, nullable)  // タレントの受け取り・コメント
    ManagerNote    (string, max:1000, nullable)  // 上長からのフィードバックメモ
    NextPeriodFocus(string, max:500, nullable)   // 次期に向けた重点テーマ
    SatisfactionScore (int, nullable, 1〜5)       // 面談満足度（タレント自己申告）
    CompletedAt    (DateTimeOffset, nullable)
```

**受入基準**:
```
Given: 評価期間が「確定（Confirmation）」フェーズである
When:  上長がフィードバック面談記録を登録する
Then:  面談内容・タレントの反応・次期重点テーマが保存される

Given: フィードバック面談が未実施のタレントがいる
When:  上長がチーム管理画面を見る
Then:  面談未実施のタレントが視覚的にハイライトされる
```

---

### ENHANCE-5-2: 評価スコアの相対調整（キャリブレーション）

**現状**: 上長評価はスコア（1〜5）の入力のみ。部門間の評価基準のばらつきを調整する機能がない。

**課題**: MDC実務では「複数マネージャーが参加するキャリブレーション（評価目線合わせ）」が重要。部門Aの「4」と部門Bの「4」が同等かを確認する場がない。

**改善内容**:

CommitteeSession に追加:
```
  - CalibrationNotes (string, max:2000, nullable)
    // キャリブレーション記録（部門間評価の調整・確認事項）
```

EvaluationPeriodに追加:
```
  - CalibrationStatus (enum): NotStarted | InProgress | Completed
  - CalibrationCompletedAt (DateTimeOffset, nullable)
```

**画面**:
- 委員会セッション記録に「キャリブレーション所見」フィールドを追加

## Part 6: 目標設定・評価画面の改善

### ENHANCE-6-1: 目標入力画面の改善（記入例・ガイダンス付き）

**現状**: 目標設定フォームは「タイトル」と「詳細」のみ。記入例やガイダンスがなく、質のばらつきが大きい。

**課題**: リクルート実例・OKR実務において、「具体的な記入例」が記入品質の向上に有効。特に新入社員・若手は目標設定の書き方を迷う。

**改善内容**:

目標設定フォームに追加:
- カテゴリ別の記入例（プレースホルダー）をリッチに
- KPIフィールドに具体的な測定指標の例示
- 「良い目標の要件」のインラインヒント（SMARTの観点）

カテゴリ別記入例:
```
Will（やりたいこと）:
  例: 「来期中にアーキテクトレビューを単独で担当し、チームの設計品質向上に貢献する」
  KPI例: 「設計レビューで指摘がゼロの要件定義書を5件作成」

Can（できること）:
  例: 「TypeScriptを活用した型安全な設計の社内標準化を推進する」
  KPI例: 「型エラーによるリグレッション数を前期比50%削減」

Must（やるべきこと）:
  例: 「Q2のリリースまでに認証機能のセキュリティ強化を完了させる」
  KPI例: 「脆弱性診断でCritical/High 0件を達成」
```

### ENHANCE-6-2: 自己評価の定量・定性記入フィールド分離

**現状**: 自己評価はスコア（1〜5）とコメントテキストのみ。目標値と実績値の対比が視覚的に分かりにくい。

**改善内容**:

SelfEvaluation に追加:
```
  - actualValue      (string, max:100, nullable)  // 実績値（目標KPIに対応）
  - achievementReason(string, max:500)           // 達成・未達の理由分析
  - nextPeriodAction (string, max:300, nullable)  // 次期に向けた改善アクション
```

自己評価画面:
- 目標のKPI/目標値を参照表示
- 実績値入力フィールドを追加
- 「達成度の理由（定性）」フィールドを追加

## Part 7: ダッシュボードの強化

### ENHANCE-7-1: ホームダッシュボードへの状況サマリー追加

**現状**: ホームは「クイックアクション」と「機能一覧」のみ。システム全体の状況が一目で分からない。

**改善内容**:

ロール別にダッシュボードカードを追加:

**タレント向け**:
- 今期目標の進捗率サマリー（円グラフ or プログレスバー）
- 次回1on1予定日
- キャリアプランの最終更新日
- 承認待ちスキル件数

**上長向け**:
- 部下の目標設定完了率
- 承認待ちスキル申請件数
- 1on1実施率（今月）
- 評価期限までの残日数

**管理職・幹部向け**:
- 9ボックスのサマリー（各セルの人数）
- 次回委員会セッションの予定日
- アクションアイテム未対応件数
- 重点管理人物の育成計画更新状況

## スコープ外（作らないもの）

本仕様の範囲外として明示的に除外するもの:

- 給与・報酬管理（ミッショングレード制等の報酬連動機能）
- 採用管理（タレントアクイジション）
- 勤怠・労務管理との連携
- AI/MLによるスキル推薦・キャリアパス自動提案
- モバイルアプリ（Webブラウザのみを対象とする）
- マルチテナント対応（単一組織内のシステムとする）

```
【4月（上期初）】

  ↓ Must 目標設定（KPI確定）

【5〜6月】
  ↓ 月次1on1（進捗・課題確認）

【7月（四半期末）】
  ↓ 四半期中間確認（目標妥当性検証・修正）
  ↓ キャリブレーション（上長間の評価基準合わせ）

【8〜9月】
  ↓ 月次1on1継続

【10月（上期末）】
  ↓ 自己評価入力
  ↓ 上長評価（1次評価）
  ↓ 2次評価・最終確定

【10〜11月：人材開発委員会（部レベル）】
  ↓ タレントプロファイル事前配布
  ↓ 9ボックスでの分類
  ↓ 重点管理人物の見直し・育成計画レビュー
  ↓ 後継者候補の確認（ReadyNow/ReadySoon/MidTerm）
  ↓ アクションアイテム決定

【11月：人材開発委員会（経営レベル）】
  ↓ 部長・執行役員候補の審議
  ↓ 会社横断の人材最適化議論

【12月】
  ↓ フィードバック面談（評価結果の伝達・納得）
  ↓ 次期目標設定のインプット

【1月（下期初）】
  ↓ 下期 Will-Can-Must 更新
  ↓ 繰り返し
```
