## 1. 背景・目的（Why）

### 1.1 課題・背景

現状、エンジニアのキャリア開発において以下の問題が生じている。

- **Will-Can-Mustが分断されている**: キャリアの方向性（Will）・現在のスキル（Can）・今期の目標（Must）が別々に管理されており、全体像を一画面で確認できない
- **目標設定との乖離に気づけない**: 今期の目標（Must）がキャリアプラン（Will）と合っているかを上司も部下も把握しにくく、注力すべきことがぶれやすい
- **現在地が見えない**: エンジニアが「自分がどこにいるのか」を体系的に把握できず、チャレンジの根拠を持ちにくい
- **上長がキャリア志向を把握できない**: 面談や評価のたびにキャリア志向を確認する必要があり、継続的なサポートが難しい

### 1.2 解決する価値

- **タレント**: 中長期キャリアプラン（Will）・承認済みスキル（Can）・今期目標（Must）を同一画面で確認でき、現在地を認識した上でチャレンジできる
- **上長**: 部下のキャリア志向を常時把握でき、目標設定・育成方針のブレを防ぐ。コメントで継続的にサポートできる
- **組織（Senior/Admin）**: 組織全体のキャリアプランを俯瞰でき、人材配置・育成方針の意思決定に活用できる

Constitution.md との対応:
- スコープ「個人の中長期キャリアプランの管理（v1は本システム内で完結）」
- 成功定義「エンジニアが自分のスキル・目標・評価履歴を一元的に参照できる」

### 1.3 スコープ外（やらないこと）

- キャリアプランと人事異動・配置転換の自動マッチング（SPEC-PROJ-001 実装後に検討）
- 外部キャリア相談ツール・学習プラットフォームとの連携
- 360度フィードバック（同僚からのキャリアフィードバック）— v2以降
- AIによるキャリアパス提案

## 2. 要件（What）

### 2.1 用語定義

| 用語 | 定義 |
|------|------|
| キャリアプラン | タレントが記録する中長期の成長目標と今期の注力テーマ。Willを中心に構成される |
| Will | なりたい姿・やりたいこと（3〜5年後の目標） |
| Can | 現在できること（SPEC-SKILL-001 の承認済みスキル） |
| Must | やるべきこと（SPEC-EVAL-001 の今期評価目標） |
| 統合ビュー | Will-Can-Mustを同一ページで確認できる画面 |
| 期 | キャリアプランを管理する単位。年度単位（例: 2026年度） |
| 今期 | `PeriodYear = 現在のカレンダー年（1月1日〜12月31日）` を今期と判定する。例: 2026年のいつでも `PeriodYear = 2026` が今期 |

### 2.2 機能要件

#### REQ-01: キャリアプランの作成・編集（タレント）

| 優先度 | 要件 |
|--------|------|
| Must | タレントが今期のキャリアプランを作成できる |
| Must | 中長期目標（3〜5年後のなりたい姿）を自由記述で記録できる |
| Must | 中期目標（1〜2年で達成したいこと）を自由記述で記録できる |
| Must | 今期の注力テーマ（キャリアプランと今期目標をつなぐもの）を記録できる |
| Must | 保存と同時に上長・Admin から閲覧可能になる（下書き/公開の区別なし。保存＝公開） |

#### REQ-02: Will-Can-Must 統合ビュー

| 優先度 | 要件 |
|--------|------|
| Must | キャリアプランページ上で、今期目標（SPEC-EVAL-001 の評価目標）を参照表示できる |
| Must | キャリアプランページ上で、承認済みスキル（SPEC-SKILL-001）を参照表示できる |
| Must | Will（キャリアプラン）・Can（スキル）・Must（今期目標）を同一ページで確認できる |
| Should | 上長が部下のキャリアプランページを閲覧する際も同じ統合ビューが表示される |

#### REQ-03: 上長コメント・フィードバック

| 優先度 | 要件 |
|--------|------|
| Must | 直属上長がタレントのキャリアプランにコメントを記録できる |
| Must | コメントはタレントから閲覧できる |
| Must | コメントは追記のみ（編集・削除不可。履歴として残る） |
| Should | コメントの投稿日時・投稿者が記録される |

#### REQ-04: 履歴管理

| 優先度 | 要件 |
|--------|------|
| Must | 年度ごとにキャリアプランが独立して管理される |
| Must | 過去の期のプランを読み取り専用で参照できる |
| Must | 新しい期のプランを作成しても過去の期のプランは上書きされない |
| Could | 前期のキャリアプランを雛形として新期プランを作成できる |

#### REQ-05: 組織俯瞰ビュー（Senior/Executive/Admin 向け）

| 優先度 | 要件 |
|--------|------|
| Must | Senior/Executive/Admin が全タレントのキャリアプラン要約を一覧で表示できる |
| Must | タレント名・中長期目標・今期注力テーマが一覧に含まれる |
| Must | Talent/Manager ロールはこのビューにアクセスできない（403） |

### 2.3 アクセス制御

| 操作 | Talent | Manager | Senior | Executive | Admin |
|------|--------|---------|--------|-----------|-------|
| 自分のプランを作成・編集 | ✅ | — | — | — | — |
| 自分のプランを閲覧 | ✅ | — | — | — | — |
| 部下のプランを閲覧 | — | ✅（直属のみ） | — | — | — |
| 部下のプランにコメント | — | ✅（直属のみ） | — | — | — |
| 組織俯瞰ビュー | ❌ | ❌ | ✅ | ✅ | ✅ |

## 3. 受入基準

### REQ-01: キャリアプランの作成・編集

**AC-01-01: 今期プランを新規作成できる**
- Given: タレントがログイン済みで、今期（当年度）のキャリアプランが未作成である
- When: キャリアプランページを開く
- Then: 空のキャリアプランフォームが表示され、作成できる状態になっている

**AC-01-02: キャリアプランを下書き保存できる**
- Given: タレントがキャリアプランフォームに中長期目標・注力テーマを入力した
- When: 「保存」ボタンをクリックする
- Then: プランが保存され、「保存済み」と表示される

**AC-01-03: 保存済みキャリアプランを編集できる**
- Given: タレントが今期のキャリアプランを保存済みである
- When: キャリアプランページを開いて内容を変更し保存する
- Then: 変更が保存される

**AC-01-04: 過去の期のプランは編集できない**
- Given: タレントが過去の期（今期以外）のプランを表示している
- When: 過去期のプランページを開く
- Then: 入力フォームは表示されず読み取り専用となる

### REQ-02: Will-Can-Must 統合ビュー

**AC-02-01: 統合ビューにWill・Can・Mustが表示される**
- Given: タレントが今期のキャリアプランを作成済みで、承認済みスキルが存在し、今期の評価目標が登録済みである
- When: キャリアプランページを開く
- Then: キャリアプラン（Will）・承認済みスキル一覧（Can）・今期評価目標（Must）が同一ページに表示される

**AC-02-02: 今期目標が未登録の場合の表示**
- Given: タレントに今期の評価目標が登録されていない
- When: キャリアプランページを開く
- Then: Must セクションに「今期目標が未設定です」と表示される

**AC-02-03: 承認済みスキルが0件の場合の表示**
- Given: タレントに承認済みスキルが存在しない
- When: キャリアプランページを開く
- Then: Can セクションに「承認済みスキルがありません」と表示される

**AC-02-04: 上長が部下の統合ビューを閲覧できる**
- Given: 上長がログイン済みで、部下のキャリアプランページにアクセスする
- When: `/career/[talentId]` を開く
- Then: 部下のWill・Can・Mustが同一ページで表示される（コメント入力フォームが表示される）

### REQ-03: 上長コメント・フィードバック

**AC-03-01: 直属上長がコメントを投稿できる**
- Given: 上長がログイン済みで、直属部下のキャリアプランページを表示している
- When: コメントを入力して「コメントを送信」ボタンをクリックする
- Then: コメントが保存され、投稿者名・投稿日時とともに表示される

**AC-03-02: タレントが上長コメントを閲覧できる**
- Given: 上長がコメントを投稿済みである
- When: タレントが自分のキャリアプランページを開く
- Then: 上長のコメントが表示される

**AC-03-03: 直属上長以外はUIでコメントできない**
- Given: Senior ロールのユーザーがタレントのキャリアプランページを表示している
- When: コメントを投稿しようとする
- Then: コメント入力フォームは表示されない（閲覧のみ）

**AC-03-03b: 直属上長以外はAPIでもコメントできない**
- Given: 直属上長でないユーザー（Senior・Admin 含む）が認証済みである
- When: `POST /api/career-plans/{id}/comments?requesterId={userId}` を実行する
- Then: 403 が返り、コメントは保存されない

**AC-03-04: 空コメントは投稿できない**
- Given: 上長がコメント入力欄を空白のままにしている
- When: 「コメントを送信」ボタンをクリックする
- Then: エラーが表示され、投稿されない（400）

### REQ-04: 履歴管理

**AC-04-01: 新期のプランを作成しても旧期は保持される**
- Given: タレントが2026年度のキャリアプランを保存済みである
- When: 2027年度のキャリアプランを新規作成する
- Then: 2026年度のプランはアーカイブされたまま参照可能であり、上書きされない

**AC-04-02: 過去の期を選択して参照できる**
- Given: タレントが複数年度のキャリアプランを持っている
- When: 期選択UIで過去の年度を選択する
- Then: 選択した年度のキャリアプランが読み取り専用で表示される

### REQ-05: 組織俯瞰ビュー

**AC-05-01: Senior以上が組織一覧を閲覧できる**
- Given: Senior ロールでログイン済みである
- When: 組織キャリアプラン一覧ページを開く
- Then: タレント全員の名前・中長期目標・今期注力テーマが一覧表示される（v1: ページングなし・全件表示）

**AC-05-02: Talent/Managerは組織一覧にアクセスできない**
- Given: Talent または Manager ロールでログイン済みである
- When: 組織キャリアプラン一覧の API にアクセスする
- Then: 403 が返る

## 4. 非機能要件

| 項目 | 要件 |
|------|------|
| データ保護 | キャリアプランは個人情報として扱い、本人・直属上長・Admin のみアクセス可能 |
| 文字数上限 | 各テキストフィールドは最大 1,000 文字 |
| データ保持 | キャリアプランは退職後も **7 年間**保持（Constitution.md セクション2.3: 労働基準法第109条準拠） |

## 5. データモデル（概略）

```
CareerPlan
├── Id: Guid
├── UserId: Guid（タレント）
├── PeriodYear: int（例: 2026。今期 = 現在のカレンダー年）
├── LongTermGoal: string（3〜5年後のなりたい姿）
├── MediumTermGoal: string（1〜2年の中期目標）
├── CurrentFocus: string（今期の注力テーマ）
├── CreatedAt: DateTimeOffset
└── UpdatedAt: DateTimeOffset
※ Status フィールドなし。保存と同時に公開状態となる。

CareerPlanComment
├── Id: Guid
├── CareerPlanId: Guid
├── AuthorId: Guid（上長）
├── Content: string
└── CreatedAt: DateTimeOffset
```

統合ビューは CareerPlan + UserSkill（Can）+ EvaluationGoal（Must）の読み取り集約で実現する。
EvaluationGoal は SPEC-EVAL-001 で定義済みの目標エンティティを参照する。
