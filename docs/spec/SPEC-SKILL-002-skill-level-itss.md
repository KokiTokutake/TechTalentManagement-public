## 1. 背景・目的（Why）

### 1.1 解決する問題

現状のスキル評価（SPEC-SKILL-001）は「1〜5のスコア」のみで、スコアの意味が個人・組織によって解釈が異なる。また、テクニカルスキル以外のコンピテンシー（問題解決力・コミュニケーション力等）が評価対象になっていない。

### 1.2 ビジネス価値

- 経産省・IPAのIT スキル標準（ITSS）Level 1〜7を参考にしたスキルレベル定義を整備することで、組織内でスキル評価の共通言語が生まれる
- iCD（IT人材育成支援ツール）の4軸（テクノロジ・メソドロジ・ビジネスインダストリ・共通）を参考にコンピテンシー評価を追加することで、テクニカルスキル以外の成長も可視化できる
- スキルマップとの連動（SPEC-SKILL-001）を強化し、組織全体のケイパビリティギャップを特定しやすくする

### 1.3 対象ユーザー

| ユーザー | 権限 |
|---------|------|
| タレント（一般エンジニア） | 自分のスキル・コンピテンシーの自己評価 |
| 上長（マネージャー） | 配下タレントのスキル・コンピテンシー評価 |
| 管理者（HR） | スキルマスタ・コンピテンシーマスタの管理 |
| 管理者（人事評価チーム） | 全タレントのスキル・コンピテンシー状況の閲覧 |

## 2. 要件（What）

### REQ-01: ITSSベースのスキルレベル定義 【Must】

スキルマスタの各スキルに、1〜7段階のレベル定義テキストを設定できる：

| レベル | 目安 |
|--------|------|
| 1 | 概念的理解。学習中または経験ゼロ |
| 2 | 基礎的な作業を上位者のサポートで実施可能 |
| 3 | 一般的な業務を単独で実施可能 |
| 4 | 複雑な業務を担当し、後輩を指導できる |
| 5 | 高度な専門業務を担当。プロジェクトをリードできる |
| 6 | 組織横断で専門知識を適用。標準策定に関与 |
| 7 | 業界最高水準。外部に対しても影響力を持つ |

既存の1〜5スケールデータを1〜7スケールに一括変換する管理者向け移行ツールを提供する。移行前に管理者が変換プレビュー（変換ルール: 1→1, 2→2, 3→3, 4→5, 5→7）を確認・承認してから実行する（マイグレーション対応必須）。

### REQ-02: スキルレベル定義の参照表示 【Must】

タレントがスキル自己評価を行う際、各レベルの定義テキストをプルダウンまたはツールチップで参照できる。評価フォーム内で「このレベルとは？」の確認ができる。

### REQ-03: コンピテンシー評価カテゴリの追加 【Should】

iCDの4軸を参考にした4カテゴリのコンピテンシーを評価できる：
1. **テクノロジコンピテンシー**: 技術的問題解決・アーキテクチャ設計・品質意識
2. **メソドロジコンピテンシー**: プロジェクト管理・改善推進・ドキュメンテーション
3. **ビジネスインダストリコンピテンシー**: ビジネス理解・顧客視点・業界知識
4. **共通コンピテンシー**: コミュニケーション・チームワーク・リーダーシップ・自律性

各コンピテンシー項目を管理者が設定できるマスタとして管理する。

### REQ-04: 上長評価とのスキルギャップ可視化 【Should】

タレントの自己評価と上長評価を並べて表示し、乖離（ギャップ）が大きいスキル・コンピテンシーをハイライトする。ギャップ閾値（例: 2レベル以上の差）を設定可能にする。

### REQ-05: スキルマップへの反映 【Should】

既存のスキルマップ（SPEC-SKILL-001）に、コンピテンシー評価を別タブで追加表示する。部門・ロール別のコンピテンシー平均値をヒートマップで表示する。

### REQ-06: スキルレベルに基づくキャリアパス提示 【Could】

タレントの現在のスキルレベルと組み合わせて、「次のポジションに必要なスキル」を参照できるキャリアパス表を提供する（マスタデータは管理者が設定）。

---

## 3. スコープ外（作らないこと）

- IPAの実際のITSSアセスメントツールとの連携・認定取得フロー
- 外部資格（AWS認定・情報処理技術者試験等）の自動取得・連携
- AIによるスキルレベルの自動推定

## 4. 受入基準

### REQ-01: ITSSベースのスキルレベル定義

**AC-01-01: レベル定義の設定**
- Given: 管理者がスキルマスタ「Python」の編集画面を開いている
- When: Level 1〜7それぞれに定義テキストを入力して保存する
- Then: レベル定義が保存され、タレントのスキル評価フォームで参照できるようになる

**AC-01-02: 未設定スキルのフォールバック**
- Given: スキルマスタに登録されているが、レベル定義が未設定のスキルが存在する
- When: タレントがそのスキルの評価フォームを開く
- Then: 標準レベル定義（汎用テキスト）がフォールバックとして表示される

**AC-01-03: 移行ツールによるスケール変換**
- Given: 管理者が移行ツール画面を開き、変換ルール（1→1, 2→2, 3→3, 4→5, 5→7）のプレビューを確認している
- When: 「移行を実行」ボタンをクリックして確認ダイアログで「実行する」を選択する
- Then: 全タレントの既存スキル評価データが新スケールに変換される。変換前データはバックアップとして保持され、移行ログが記録される

### REQ-02: スキルレベル定義の参照表示

**AC-02-01: レベル定義の参照**
- Given: タレントがスキル自己評価フォームを開いている
- When: レベルセレクタの「?」アイコンをクリック、またはレベル項目をホバーする
- Then: そのレベルの定義テキストがツールチップ/モーダルで表示される

### REQ-03: コンピテンシー評価カテゴリ

**AC-03-01: コンピテンシー評価の入力**
- Given: タレントがスキル評価画面の「コンピテンシー」タブを開いている
- When: 各コンピテンシー項目（例: コミュニケーション力）に対してレベル1〜5を選択して保存する
- Then: コンピテンシー評価が保存され、上長の評価画面にも表示される

**AC-03-02: コンピテンシーマスタの管理**
- Given: 管理者がコンピテンシーマスタ管理画面を開いている
- When: 新規コンピテンシー項目「AI活用力」をカテゴリ「テクノロジ」で追加する
- Then: 次の評価期間から全タレントのコンピテンシー評価フォームに「AI活用力」が追加される

### REQ-04: スキルギャップの可視化

**AC-04-01: 自己評価と上長評価の比較表示**
- Given: タレントAのスキル「Java」に自己評価4・上長評価2が存在する
- When: スキル評価の比較画面を開く
- Then: 「Java」の行に自己評価バー（4）と上長評価バー（2）が並んで表示され、ギャップ「-2」が強調表示される

**AC-04-02: 大きなギャップのアラート**
- Given: ギャップ閾値が「2以上」に設定されている
- When: 自己評価と上長評価の差が2以上のスキルが存在する
- Then: そのスキルが「要確認」セクションに自動的に分類される

### REQ-05: スキルマップへの反映

**AC-05-01: コンピテンシータブの追加**
- Given: スキルマップ画面が表示されている
- When: 「コンピテンシー」タブをクリックする
- Then: 部門・ロール別のコンピテンシー平均値がヒートマップ形式で表示される（高スコア=濃い色）

## 5. データモデル（概要）

```
# 既存の SkillMaster を拡張
SkillLevelDefinition {
  skillId: string → SkillMaster.id  (PK複合)
  level: int (1〜7)                 (PK複合)
  description: string (max: 1000)  # レベルの説明
  examples: string | null (max: 2000)  # 行動例
}

CompetencyMaster {
  id: string (ULID)
  category: enum { Technology, Methodology, BusinessIndustry, Common }
  name: string (max: 100)
  description: string | null (max: 500)
  displayOrder: int
  isActive: boolean (default: true)
  createdAt: datetime
}

CompetencyEvaluation {
  id: string (ULID)
  talentId: string → User.id
  evaluatorId: string → User.id
  competencyId: string → CompetencyMaster.id
  periodId: string → EvaluationPeriod.id
  level: int (1〜5)
  comment: string | null (max: 500)
  evaluatorType: enum { Self, Manager }
  createdAt: datetime
  updatedAt: datetime
  # Unique: talentId + evaluatorId + competencyId + periodId + evaluatorType
}
```

## 6. APIエンドポイント（概要）

```
GET  /api/skill-masters/{skillId}/level-definitions        → レベル定義取得
PUT  /api/skill-masters/{skillId}/level-definitions        → レベル定義一括保存（Admin）

GET  /api/competency-masters                               → コンピテンシーマスタ一覧
POST /api/competency-masters                              → コンピテンシー追加（Admin）
PUT  /api/competency-masters/{id}                         → コンピテンシー更新（Admin）

POST /api/competency-evaluations                          → コンピテンシー評価保存（Talent/Manager）
GET  /api/competency-evaluations?talentId=&periodId=      → 評価取得（Talent/Manager/MDC）

GET  /api/skill-map/competency?departmentId=&periodId=    → コンピテンシーヒートマップデータ（MDC/Senior）
```

## 7. 非機能要件

| 項目 | 要件 |
|------|------|
| マイグレーション | 既存の1〜5スケールのデータは、1→1, 2→2, 3→3, 4→5, 5→7 の変換ルールで移行する（移行前にユーザー確認を取る） |
| パフォーマンス | スキルマップ（コンピテンシータブ）の描画を3秒以内に完了する |
| 後方互換 | レベル定義未設定のスキルは既存の動作を維持する |
