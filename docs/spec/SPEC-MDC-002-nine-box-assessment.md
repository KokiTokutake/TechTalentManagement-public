## 1. 背景・目的（Why）

### 1.1 解決する問題

現状の考課システムでは「パフォーマンス（実績）」の評価のみが存在し、「ポテンシャル（将来性）」軸が欠けている。人材開発委員会（MDC）でタレントの育成方針を議論する際、感覚値に頼った議論になりやすい。

### 1.2 ビジネス価値

- GEのセッションC・リクルートの人材開発委員会でも採用されている9ボックスマトリクスを導入することで、育成投資の優先度を可視化する
- 「パフォーマンス（縦軸）×ポテンシャル（横軸）」の2軸評価により、タレントを客観的に分類し、重点管理人物の特定を体系化する
- キャリブレーション（組織横断での評価のすり合わせ）をシステムで支援する

### 1.3 対象ユーザー

| ユーザー | 権限 |
|---------|------|
| 上長 | 配下タレントの9ボックス評価を入力 |
| 管理職 | 配下チーム全員の評価を閲覧・キャリブレーション |
| 管理者（人事評価チーム） | 全タレントの9ボックスマップを閲覧・編集・エクスポート |

## 2. 要件（What）

### REQ-01: 9ボックス評価入力 【Must】

上長が配下タレントに対してパフォーマンス（Low/Mid/High）とポテンシャル（Low/Mid/High）を評価し、結果として9つのセルのいずれかに配置する。評価コメントを任意入力できる。

### REQ-02: 9ボックスマップ表示 【Must】

3×3のグリッド形式で、各セルにタレントのアバター（イニシャル）と氏名を表示する。セルごとの人数をカウント表示する。

### REQ-03: 考課期間との紐付け 【Must】

9ボックス評価は考課期間（Period）に紐付く。考課期間ごとに評価を記録し、前回比較（前期→今期）を表示できる。

### REQ-04: キャリブレーションモード 【Should】

管理職が複数チームの評価を並べて比較し、評価の分布が偏っていないか確認できる「キャリブレーション画面」を提供する。評価分布の統計（平均・標準偏差）を表示する。

**AC-04-01: キャリブレーション画面の表示**
- Given: 複数の上長がそれぞれの配下タレントの9ボックス評価を入力済みである
- When: 管理職がキャリブレーション画面を開く
- Then: チーム別・部門別の評価分布（平均パフォーマンス・平均ポテンシャル・各セルの人数）が一覧表示される

### REQ-05: フィルタ・検索 【Should】

9ボックスマップ上で特定のセル・部門・ロールでフィルタリングできる。タレント名で検索してハイライト表示できる。

### REQ-06: 重点管理人物との連動 【Must】

上位3セル（High Performance × Mid/High Potential、Mid Performance × High Potential）にプロットされたタレントを「重点管理候補」として自動フラグを立て、MDCへ通知する。

### REQ-07: 評価履歴・推移グラフ 【Could】

タレント個人の9ボックス評価の推移（過去N期分）を折れ線グラフで表示する。

---

## 3. スコープ外（作らないこと）

- 9ボックス以外のタレント分類モデル（例: 4ボックス、バリューポートフォリオ）
- タレント自身による評価の閲覧（個人への開示はHR判断とし、システムでは制御しない）
- 給与・報酬テーブルとの連動
- 外部ベンチマークデータとの比較

## 4. 受入基準

### REQ-01: 9ボックス評価入力

**AC-01-01: 評価の入力と保存**
- Given: 上長がログイン済みで、配下タレントの評価フォームを開いている
- When: パフォーマンス「High」・ポテンシャル「Mid」を選択し、コメントを入力して「保存」をクリックする
- Then: 評価が保存され、9ボックスマップの該当セル（High Performance / Mid Potential）にタレント名が表示される

**AC-01-02: 評価の更新**
- Given: 既に評価が保存されているタレントの評価フォームを開く
- When: パフォーマンスを「Mid」に変更して保存する
- Then: 9ボックスマップの表示が更新され、変更前のセルからタレントが消え、新セルに移動する

**AC-01-03: 考課期間外の入力制限**
- Given: 現在の考課期間が「評価期間外（締め切り済み）」である
- When: 上長が評価入力フォームを開こうとする
- Then: 「評価期間が終了しています」とメッセージが表示され、入力フォームは無効化される

### REQ-02: 9ボックスマップ表示

**AC-02-01: グリッド表示**
- Given: 複数タレントの9ボックス評価が入力されている
- When: 9ボックスマップ画面を開く
- Then: 3×3のグリッドが表示され、各セルにタレントのイニシャルバッジが配置される。セル右上に人数バッジが表示される

**AC-02-02: タレントの詳細ポップオーバー**
- Given: 9ボックスマップが表示されている
- When: タレントのバッジをホバーまたはクリックする
- Then: 氏名・ロール・パフォーマンスコメント・ポテンシャルコメントのポップオーバーが表示される

### REQ-03: 考課期間との紐付け

**AC-03-01: 期間別表示**
- Given: 2024Q1と2024Q3の2期分の評価データが存在する
- When: 期間セレクタで「2024Q3」を選択する
- Then: 2024Q3の評価データで9ボックスマップが表示される

**AC-03-02: 前期比較表示**
- Given: タレントAが2024Q1に「Mid/Mid」・2024Q3に「High/Mid」と評価されている
- When: 2024Q3の9ボックスマップでタレントAのバッジを確認する
- Then: バッジに「↑」矢印が表示され、前期のセルからの移動を示す

### REQ-06: 重点管理人物との連動

**AC-06-01: 重点管理候補の自動フラグ**
- Given: タレントAが「High Performance / High Potential」セルに配置されている
- When: MDCの重点管理人物一覧を開く
- Then: タレントAが「重点管理候補」として表示される（自動推薦フラグ付き）

**AC-06-02: 通知**
- Given: 9ボックス評価の入力が完了し、重点管理候補が前期から変化した
- When: システムが変化を検知する
- Then: 管理者（人事評価チーム）にシステム内通知が送信される

## 5. データモデル（概要）

```
NineBoxAssessment {
  id: string (ULID)
  talentId: string → User.id
  evaluatorId: string → User.id  # 評価した上長
  periodId: string → EvaluationPeriod.id
  performance: enum { Low, Mid, High }
  potential: enum { Low, Mid, High }
  performanceComment: string | null (max: 1000)
  potentialComment: string | null (max: 1000)
  isHighPotentialFlag: boolean  # 自動計算
  createdAt: datetime
  updatedAt: datetime
  submittedAt: datetime | null
}

# ボックスラベル（参照データ）
NineBoxCellDefinition {
  performanceLevel: enum { Low, Mid, High }
  potentialLevel: enum { Low, Mid, High }
  cellLabel: string  # "スター", "コア人材", "要観察" etc.
  description: string
  recommendedAction: string
}
```

## 6. APIエンドポイント（概要）

```
GET    /api/nine-box?periodId=&departmentId=        → 9ボックスマップデータ（MDC/Senior）
POST   /api/nine-box                                → 評価入力（Manager）
PUT    /api/nine-box/{id}                           → 評価更新（Manager）

GET    /api/nine-box/calibration?periodId=          → キャリブレーション用一覧（Senior/MDC）
GET    /api/nine-box/history?talentId=              → 個人評価履歴（Senior/MDC）

GET    /api/nine-box/cells                          → セル定義マスタ
```

## 7. 非機能要件

| 項目 | 要件 |
|------|------|
| パフォーマンス | 100名分の9ボックスマップを3秒以内に描画する |
| セキュリティ | 9ボックス評価はタレント本人に非公開（表示権限はHR/MDCが制御） |
| 整合性 | 考課期間ごとに1タレント1評価のみ許容（重複制約） |
| 監査ログ | 評価の入力・変更はすべてAuditLogに記録する |
