重要ルール — Human-in-the-Loop
🤖 AI は道具、判断は人間
Claude Code が生成したコード・仕様書草稿は、必ず人間がレビューしてから使用する。 AI の出力をそのまま PR にマージしてはならない。最終責任は人間が負う。
📋 仕様書なしの実装禁止
仕様書のステータスが approved になる前にコーディングを開始してはならない。 仕様の不備を発見した場合、勝手に解釈せず Issue で報告してオーナーの判断を待つ。
🔄 仕様変更はコードより先に
実装中に仕様変更が必要になった場合、まず仕様書を更新（PR → レビュー → マージ）し、 その後でコードを変更する。コードが仕様書に先行してはならない。
🌀 工程は反復する
7工程は1度きりの直線ではない。実装中の発見が設計工程への差し戻しを生み、 運用のフィードバックが次の企画工程を起動する。反復を恐れず、早期に前の工程に戻る。
📏 1タスク = 1PR = 80分
タスクはレビュアーが80分以内でレビューできる粒度に分割する。 大きすぎるPRはレビュー品質を下げる。細かく分割してレビューサイクルを高速化する。
🏛️ Constitution が最高権威
全ての仕様書・設計・実装は Constitution.md の原則に従う。 Constitution.md の変更は最も厳格なレビューを要し、全ステークホルダーの承認が必要。

/tasks-plan 工程4 承認済み仕様書から「1タスク=1PR=80分以内」の粒度でタスク分割する。 ✅ 対話型（担当・SP見積もり） tasks/task-list.md + GitHub Issues

工程5: 実装（Implement）
/task-start 工程5 タスクを選んでブランチを作成し、仕様書・受入基準を読み込んだ状態で実装を開始する。 ✅ 対話型（タスク選択） feature/ブランチ + コンテキストサマリー
/impl-guide 工程5 現在のタスクの仕様書・設計書・コーディングルールを読み込み、実装ガイダンスを提供する。 ✅ 対話型（実装支援） 実装ガイダンス + コード生成支援
/impl-check 工程5 実装が受入基準をすべて満たしているか、仕様書外の実装がないかを確認する。 自動照合 + 修正支援 受入基準 vs 実装チェック表
/task-done 工程5 タスク完了後のPR作成・受入基準確認・レビュアー設定を一括で行う。 ✅ 対話型（確認 + PR作成） GitHub PR + タスクステータス更新
🧪 テスト自動化（工程5 → 工程6 ブリッジ）
/test-write 工程5 工程6 仕様書の受入基準（GWT形式）から Playwright E2E テストコードを自動生成する。Spec-as-Test の中核。 自動生成 + TODO 注記 tests/e2e/spec-xxx.spec.ts
/test-run 工程5 工程6 Playwright テストを実行し、失敗したテストの原因を仕様書の AC と紐付けて分析する。 ✅ 対話型（失敗分析） テスト結果 + 失敗分析レポート
/test-report 工程5 工程6 テスト結果を仕様書の受入基準に反映し、PO レビュー用の正式レポートを生成する。 自動生成（PR コメント可） docs/guides/test-report.md + spec 更新
工程6: 検証・受入（Verify）
/accept-run 工程6 仕様書の受入基準に基づいてテストを実施し、POサインオフを取得する。 ✅ 完全対話型（基準ごとに確認） acceptance-checklist.md + POサインオフ
/spec-trace 工程6 仕様書の全要件がコードに実装されているか、逆方向も含めて確認する。 自動照合 トレーサビリティレポート
工程7: 移行・運用（Operation）
/release-prep 工程7 リリースノートの生成・デプロイチェックリスト・Gitタグ作成を実施する。 ✅ 対話型（バージョン確認 + チェック） release-notes.md + GitHub Release
/incident-handle 工程7 本番障害発生時にP1〜P4分類・初動対応・インシデントレポート作成をガイドする。 ✅ 完全対話型（症状確認 → 対応） インシデントレポート
/retro-run 工程7 KPT形式のレトロスペクティブを実施し、次サイクルへのフィードバックを記録する。 ✅ 完全対話型（KPT収集） retrospective.md + アクションIssues
🖥️ PM ツール（Web プロジェクト管理）
/pm-setup PM SDD PM ツール（tools/pm/index.html）の初期設定ウィザード。プロジェクト情報・メンバーを設定する。 ✅ 対話型（設定収集） localStorage 初期データ
/sprint-start PM 新スプリントを対話型で開始する。ゴール設定・タスク選択・SP見積もりを行う。 ✅ 完全対話型 PM ツール スプリントレコード
/sprint-end PM スプリント完了処理とふりかえりへの引継ぎを行う。velocity 記録・未完了タスク処理・/retro-run 連携。 ✅ 対話型（完了確認） PM ツール スプリント完了 + retro 連携
/pm-sync PM PM ツール（ブラウザ）↔ プロジェクトファイルの双方向同期。仕様書ステータス照合・task-list.md 再生成。 ✅ 対話型（差分確認） tasks/task-list.md・tasks/pm-data.json 更新
